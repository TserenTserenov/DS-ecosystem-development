# Карта влияния инверсии: какие обещания и доки задевает модель «IWE как клиент, платформы первичны»

### 0. Главное за 30 секунд

- Инверсия задевает **~12 доков**: **7 на переписку** (конфликт), **5 на пометку** (мелко). Остальные ≈117 обещаний — не трогает.
- Конфликты собраны в **двух местах:** (1) определение «что такое IWE» (там IWE всё ещё «сверху» над платформой); (2) онбординг / доступ / доставка руководств (там предполагается «IWE = единственный клиент»).
- **Свежая архитектура УЖЕ инвертирована:** память, данные, табло, когнитивный бриф, анализ текста — уже платформо-центричны (владелец = платформа, Neon). Это доказывает, что модель совпадает с тем, что команда уже строит, а не висит в воздухе.
- **Один разрыв не на бумаге, а в коде:** персональные руководства сейчас генерит локальный скилл IWE (не платформа). Это уже помечено на снос (по РП222), но в обещании доставки это не зафиксировано.

### 2. Реальный разрыв (код, не бумага)

**Персональные руководства генерятся локально, а должны платформой.** Сейчас обещание доставки (DP.SC.164) опирается на локальный скилл IWE (`personal-guide-render`, слой L1) + локальный планировщик. Целевая модель: платформа (Aisystant/MIM) генерит руководство, личный IWE — только вход. Скиллы уже помечены на снос (по РП222), но в обещании это не зафиксировано → читается как «IWE владеет генерацией». Это не доковая правка, а миграция кода (локальная генерация → платформенный сервис). Заводить отдельным РП после ратификации.

### 3. Рекомендация (волны с конкретными целями)

- **Волна 2 (ратификация):** нести эту карту на ИТ-встречу. Решения: согласие на инверсию + права на канон руководств. Сильный аргумент — свежая архитектура уже инвертирована (8 обещаний платформо-центричны).
- **Волна 3 (ядро, ~2 конфликта):** DP.IWE.001 §5.2 (8-слойный стек) + DP.D.095 (оговорка про канон). Меняется определение, остальное наследует.
- **Волна 4 (обещания, ~5 конфликтов + 5 пометок):** DP.SC.164/168/021/119/156 переписать; DP.SC.020/101/102/130 + DP.IWE.007 пометить владельца.
- **Волна 5 (код):** миграция генерации персональных руководств локально → платформа (отдельный РП, связать с РП222).

### 4. Что нужно от команды (повестка ИТ-встречи)

1. **Принять инверсию.** Согласны, что платформы (Aisystant/MIM) первичны и assistant-agnostic, а IWE = один из клиентов (дистрибутив рабочей среды), не ядро платформы? Меняет позиционирование IWE. Да / нет / с оговорками.
2. **Права на канон универсальных руководств.** Русский канон → одна (российская) организация; английский = перевод-проекция в Aisystant. Владелец: нейтральный держатель канона (предпочтительно) ИЛИ одна платформа владеет + лицензирует перевод? Раздельное владение отвергнуто. Юр-вопрос (российское ИП ≠ мировое юрлицо).
3. **Подтвердить: данные / память / руководства — у платформ** (мир — Aisystant, Россия — MIM), по юрисдикции, не у IWE. Касается контуров Андрея и Ильшата напрямую.
4. **Назначить владельца + срок: миграция генерации персональных руководств** (сейчас локальный скилл IWE → должен стать сервисом платформы; refinement: личный IWE = необязательный усилитель; связать с РП222). Кто берёт?
5. **Сверка по организациям (с Пашей):** Track B орг (РП285) vs продуктовые орги keystone (`iwe-platform`/`mim-school`) — пересекаются? Сколько орг по факту?
