# Программа лояльности — модель начисления баллов и бонусов

<details open>
<summary><b>0. Панель управления — все ручки на одной странице</b></summary>

Вся модель определяется небольшим набором показателей, которые хранятся в конфигурационных таблицах. Поменять один показатель = автоматически пересчитать соответствующую часть модели. На запуске значения подобраны под сообщество в 500 подписчиков.

### Принцип «один UPDATE — пересчёт всего»

- **Курс изменился** → все скидки в боте автоматически считаются по новому курсу. История оплат остаётся неизменной.
- **Базовый множитель изменился** → дневные лимиты для всех ступеней пересчитываются (потому что лимит = база × коэф. Квалификации).
- **Максимум серии изменился** → шкала серии перерисовывается (4 уровня — производные от максимума).
- **Бюджет программы изменился** → масштабируется автоматически с ростом выручки за подписку.

Изменения вступают в силу при следующем событии (без рестарта бота). Уже накопленные баллы и бонусы — не пересчитываются: история не переписывается (см. принцип П7).

### 0.1. Семь главных ручек управления

Менять при калибровке модели. Изменение каждой из этих ручек видимо отражается на эмиссии бонусов, скидке при оплате или дневном потолке начислений.

| # | Ручка | Текущее | Что определяет |
|:---:|---|:---:|---|
| 1 | **Курс бонуса** | 0.1 ₽/бонус | Сколько рублей стоит один бонус при списании. Пересматривается ежемесячно по формуле сглаживания (см. §9). |
| 2 | **Бюджет программы** | 10% выручки за подписку | Какая доля выручки тратится на программу лояльности. Масштабируется с ростом сообщества. |
| 3 | **Реферальная ставка** | 10% от платежа | Какой процент платежа приведённого пилота поступает реферу. Реферальные бонусы пропорциональны входящему доходу — не ограничиваются отдельной долей бюджета. |
| 4 | **Базовый множитель действия** | 20 | Через него вычисляется дневной лимит на одно действие для каждой ступени (`лимит = база × коэф. Квалификации`). |
| 5 | **Калибровочный множитель суточного лимита** | 8 | Сколько действий «помещается» в день: `суточный потолок = дневной лимит × множитель`. |
| 6 | **Максимум коэффициента серии** | ×2.2 при 28+ дней | Верхняя планка награды за непрерывную серию активных дней. Уровни ниже — производные (см. §8). |
| 7 | **Приветственный бонус** | 100 баллов | Разовое начисление при первой регистрации пилота. Единственный способ для Случайного получить баллы. |

<summary><b>1. Основные положения</b></summary>

## Главное обещание

> «Мы собираем данные о ваших активных действиях, чтобы помочь вам развиваться — это персональное развитие и помощь в работе. За регулярную активность платформа начисляет небольшой бонус.»

<details>
<summary><b>Что это значит на практике</b></summary>

Активные действия пилота (учёба, продукт, знание, сообщество) формируют картину его развития, которой пользуются Диагност, Навигатор и Портной для построения персонального руководства и подсказок. Параллельно эти же действия дают баллы — символическое поощрение, которое со временем накапливается в бонусы и применяется как скидка при оплате подписки, семинаров, потоков с наставниками и курсов.

**Финансовая дисциплина:** Программа лояльности стоит компании не более **10% выручки за подписку**. Бюджет программы лояльности масштабируется автоматически с ростом сообщества.

</details>

## Двенадцать принципов

### Блок А. Финансовые рамки

**П1. Прогрессивное поощрение мастерства.** Чем выше ступень ученика, тем ценнее каждое его действие. Регулярная работа над собой даёт бонус — небольшую денежную благодарность, которая со временем накапливается. Источник: требование пилота. Аналог: Amazon Prime для топ-клиентов.

**П2. Бюджет программы лояльности ≤ 10% выручки.** Жёсткое ограничение стоимости. Программа покрывает и активные действия пилотов, и реферальные выплаты — оба источника финансируются из этого бюджета пропорционально входящему доходу. Курс настраивается ежемесячно по формуле сглаживания. Минимальный гарантированный курс — **0.01 ₽/бонус** без явного решения пилота. Источник: требование пилота. Аналог: Sephora тратит ~5-7% выручки на программу лояльности.

### Блок Б. Что поощряем

**П3. Систематичность и серии.** Регулярная ежедневная работа поощряется растущим коэффициентом серии (×1.0 → ×2.2 при 4 уровнях). Один пропуск — мягкий сброс (-1 уровень). Два пропуска подряд — полный сброс до ×1.0. Источник: Duolingo streak.

**П4. Сообщество — высшая ценность (×4).** Действия в сообществе (посты, комментарии, помощь другим, принятие рефералов) умножаются на ×4. Это больше, чем личная работа (×1), продукт (×2), знание (×3). Источник: Reddit Karma, Stack Overflow Reputation.

**П5. Культура работы с ИИ — обязательный путь (×2).** Использование ИИ-инструментов (сессии в IWE, чат с ИИ, время кодинга, публикации) умножается на ×2. Поощряется не «час работы», а «час осмысленной работы с экзокортексом». Источник: позиционирование IWE.

**П6. Знание — отдельная категория (×3).** Извлечение и формализация знания (обновление Pack, добавление различений, описание методов, извлечение знаний) — ×3. Источник: академическая модель публикаций.

### Блок В. Защита и доверие

**П7. Накопление, не сгорание.** Баллы не истекают никогда. Бонусы переносятся между месяцами для всех ступеней без потолка переноса — пилот волен копить столько, сколько хочет, и тратить когда удобно. **Баллы НЕ обнуляются при обновлении модели** — пересчёт ведётся в сторону пользователя. Источник: критика Starbucks (6-мес истечение), Habitica 2017, обесценивание авиамиль.

**П8. Прозрачность курса и пути.** Курс 0.1 ₽/бонус — всегда видим в UI. Дата следующего пересмотра видна. Диапазон возможного изменения ±30% — также видим. Источник: Starbucks Rewards UI, Sephora.

**П9. Защита от накрутки и предсказуемость в UI.** В реализации: степенная зависимость от времени, суточный лимит, лимит частоты события в день. На UI показываем только итоговые баллы за действие, без формул. Сложность остаётся за кадром.

### Блок Г. Мастерство и UX

**П10. Прогрессивность по 12 ступеням.** Чем выше ступень ученика, тем ценнее то же действие. Коэффициент Квалификации растёт от 0 (Случайный) до 5.0 (Общественный деятель). Подробности см. §7.

**П11. Простота для новичка.** **Случайный (ступень 1) не получает баллов** (коэф. Квалификации = 0) — модель не дробится в микро-цифры. Приветственный бонус 100 баллов при первой регистрации даёт первый сигнал, дальше — стимул дойти до Практикующего. Источник: Starbucks 15-секундное правило. Анти-аналог: Habitica.

**П12. Видимость пути до награды.** В UI прогресс-бар «До бесплатной подписки 740 ₽ из 1 000 ₽». Это единственный элемент на главной странице. Источник: Duolingo «XP to next league», Starbucks «12⭐ to reward».

<details open>
<summary><b>2. Три объекта учёта</b></summary>

В программе лояльности IWE одновременно существуют три разных объекта учёта. Они описывают одну и ту же активность пользователя, но с разных точек зрения: как история (баллы), как экономический инструмент (бонусы) и как квалификационный статус (Ступень Ученика). Разделение принципиально — оно позволяет баллам никогда не обесцениваться, а бонусам при этом оставаться под контролем бюджета.

| Объект | Что считает | Убывает? | Курс к ₽ |
|---|---|---|---|
| **Баллы** | Накопленные баллы — сумма всех начислений за всё время | **Никогда** | Нет |
| **Бонусы** | Скидочный ресурс: накапливается из баллов с учётом дневного и переносного лимитов; тратится при оплате | Да (тратятся при оплате) | **Есть (0.1 ₽/бонус)** |
| **Ступень Ученика** | Профиль ученика (читается из цифрового двойника, не вычисляется этой моделью) | Нет | Нет |

**Ключевое правило:** пользователь видит «Баллы: 11 200» (история) и «Доступная скидка: 1 120 ₽» (бонусы в рублях). Баллы потратить нельзя. Курс применяется только к бонусам в момент оплаты.

**Накопление без потолка:** бонусы переносятся между месяцами без верхнего лимита. Пилот волен копить столько, сколько хочет, и тратить когда удобно — на подписку, семинары, потоки с наставниками, курсы.

</details>

<details open>
<summary><b>3. Бюджетная структура</b></summary>

Программа лояльности финансируется из единого бюджета в 10% от выручки за подписку. Внутри него — две составляющие: вознаграждение за активные действия пилотов и реферальные выплаты за приведённых подписчиков.

> **Реферальные выплаты не ограничены отдельной долей бюджета.** Чем больше людей приведено и оплатило подписку, тем больше реферальных бонусов — и тем больше входящая выручка. Программа балансируется автоматически: бонус выплачивается с каждого платежа, который уже поступил в выручку.

**При N = 500 подписчиков (ориентир):**

| Статья | Сумма |
|---|---|
| Выручка за подписку | 500 000 ₽/мес |
| **Бюджет программы лояльности (10%)** | **50 000 ₽/мес** |
| **Плановая эмиссия бонусов** | **500 000 бонусов/мес** |

Эмиссия рассчитывается из курса: 50 000 ₽ ÷ 0.1 ₽/бонус = 500 000 бонусов. Это сумма за все источники начисления — активные действия + рефералы. Если поток рефералов окажется выше прогноза, общий объём эмиссии вырастет пропорционально входящей выручке от приведённых пилотов; это нормальное поведение программы.

</details>

<details open>
<summary><b>4. Формула начисления баллов</b></summary>

Баллы начисляются за каждое активное действие пользователя. Итоговое число баллов зависит от трёх факторов: насколько ценно само действие (вес), насколько квалифицирован ученик (коэффициент Квалификации) и насколько регулярно он занимается (коэффициент серии).

### Общая формула

```
баллы_за_действие = вес_действия × коэффициент_Квалификации × коэффициент_серии
```

**Что означает каждый множитель:**

| Множитель | Что означает | Как вычисляется |
|---|---|---|
| **вес действия** | Ценность конкретного действия: усилие × редкость × групповая ценность | Для действий с усилием: фактор усилия × редкость × коэф. группы. Для маркерных: 1 × редкость × коэф. группы |
| **коэффициент Квалификации** | Чем выше квалификация ученика, тем ценнее то же действие | Таблица §7, от ×0 до ×5.0 |
| **коэффициент серии** | Бонус за непрерывную регулярность занятий | ×1.0 … ×2.2 (см. §8) |

### Ограничения начислений

Чтобы никто не зарабатывал неограниченно много баллов за один день, введены два уровня ограничений.

**Первый уровень — лимит на одно действие:**
Баллы за одно действие не могут превысить максимум для данной квалификации. Дневной лимит действия = базовый множитель (20) × коэф. Квалификации. Это значит, что одно действие Реформатора (×4.0) ценится вчетверо выше, чем то же действие Практикующего (×0.4), — и эта разница ограничена сверху.

**Второй уровень — суточный потолок:**
Сумма всех баллов за день не может превысить суточный лимит начислений = дневной лимит действия × калибровочный множитель (8).

```
Дневной лимит действия    = 20 × коэф. Квалификации
Суточный лимит начислений = дневной лимит действия × 8

Итоговые баллы за действие = min(баллы_за_действие, дневной лимит действия)

Сумма_за_день += Итоговые_баллы_за_действие
Если Сумма_за_день > Суточный_лимит:
    последующие баллы за день = 0 (или остаток до лимита)
```

При достижении дневного лимита последующие действия не дают баллов в этот день (но это никак не блокирует сами действия — пилот продолжает заниматься).

</details>

<details open>
<summary><b>5. Активные действия — два типа и четыре группы</b></summary>

Все активные действия разделены на два типа по принципу: имеет ли значение, сколько времени потрачено.

### 5.1. Тип А — С усилием (время имеет значение)

Действия, где время — содержательный вклад: завершение урока, рабочего продукта, время кодинга, публикация контента и др.

```
фактор усилия     = минуты_усилий ^ 0.6
вес действия      = фактор_усилия × коэф. редкости × коэф. группы
```

Зависимость степенная (показатель 0.6): удвоение усилий даёт +52% к весу, а не ×2 — это защита от искусственного растягивания задач. Час работы = 17.4 ед., два часа = 27.2 ед., четыре часа = 42.5 ед.

### 5.2. Тип Б — Маркерные (время не значимо)

Действие зафиксировано, но время не важно: IWE-сессия проведена, Pack обновлён, реферал принял приглашение и др.

```
вес действия = 1 × коэф. редкости × коэф. группы
```

Каждое маркерное действие имеет единичный вес до применения редкости и групповой ценности.

### 5.3. Четыре группы деятельности (коэффициент группы)

| Группа | Коэф. группы | Что внутри |
|---|:---:|---|
| **G1. Личное** | ×1 | Уроки, тренировки, тесты — личное развитие ученика |
| **G2. Продукт + культура ИИ** | ×2 | Публикации, кодинг, рабочие продукты, сессии в IWE |
| **G3. Знание** | ×3 | Извлечение знаний в Pack, добавление различений |
| **G4. Сообщество** | ×4 | Посты, комментарии, помощь другим, приведение рефералов |

</details>

<summary><b>7. Шкала квалификации</b></summary>

Коэффициент Квалификации — множитель, который отражает глубину вклада ученика в систему: чем выше квалификация, тем ценнее его активность. Не просто «больше баллов», а именно признание того, что действия более продвинутого ученика имеют большее значение для платформы.

**Ступени читаются из цифрового двойника.** Модель лояльности только использует — не вычисляет. Переход между ступенями определяется Диагностом и не зависит от накопленных баллов.

<summary><b>8. Коэффициент серии (страйк)</b></summary>

Коэффициент серии — это бонус за непрерывную регулярность занятий. Идея проста: тот, кто занимается каждый день, получает прогрессивно больше баллов за те же действия. Это мотивирует не к разовым марафонам, а к устойчивой привычке. Серия накапливается по количеству подряд идущих активных дней; пропуск одного дня не обнуляет серию, а лишь опускает её на один уровень — это «мягкий сброс».

| Серия (дней подряд) | Коэф. серии |
|:---:|:---:|
| 0–6 | ×1.00 |
| 7–13 | ×1.30 |
| 14–27 | ×1.70 |
| 28+ | **×2.20** |

В v4.2 было пять уровней (×1.0 → ×1.2 → ×1.5 → ×1.8 → ×2.0). В v4.3 шкала сокращена до четырёх уровней с более резким ростом множителя на каждой ступеньке — это даёт более чёткий стимул дойти до месячной устойчивости.

**Мягкий сброс** — пропуск одного дня: серия опускается на один уровень, не обнуляется. Пропуск двух дней подряд — сброс до ×1.00.

**Защита от накрутки:** для зачёта дня серии требуется хотя бы одно действие с ненулевым вложенным временем. Исключает «токен-коммит в 00:59» только ради сохранения серии.

**Важно про эффективные баллы в таблицах §6.** Они показаны при стандартном условии «страйк 7–13 дней» — это даёт ×1.3. При пересчёте на свою ступень и страйк нужно сначала снять базовый множитель (`вес = эффективные / 1.3`), затем умножить на актуальный коэффициент серии и коэффициент Квалификации.

<summary><b>9. Курс бонусов</b></summary>

Курс — это сколько рублей стоит один бонус при оплате подписки. Курс нельзя установить один раз навсегда: по мере роста платформы и изменения активности пользователей реальная эмиссия бонусов меняется, и курс нужно пересматривать. Чтобы курс не прыгал от месяца к месяцу, используется экспоненциальное скользящее среднее — оно «помнит» историю нескольких месяцев и сглаживает колебания.

### Стартовый курс

**Курс = 0.1 ₽/бонус** — установлен вручную из расчёта N=500, исходя из бюджета лояльности (10% выручки за подписку) и плановой эмиссии бонусов по типичной активной воронке пилотов.

В v4.2 был стартовый курс 0.05 ₽/бонус и базовый множитель 200. В v4.3 курс удвоен (0.1), а базовый множитель уменьшен в 10 раз (20) — итоговая эмиссия в рублях остаётся примерно той же, но рублёвая ценность каждого бонуса для пилота вдвое выше, и количество бонусов в обращении меньше — это упрощает восприятие.

### Механизм обновления

Каждое 1-е число месяца курс пересчитывается по формуле скользящего среднего:

```
Новый курс  = Предыдущий курс × (1 − α) + Сырой курс × α
Сырой курс  = Бюджет программы лояльности / Эмиссия бонусов за прошлый месяц
α = 0.3   (память примерно 3–4 месяца)

Новый курс  = clamp(Новый курс, нижний порог, верхний порог)
Нижний порог = 0.01 ₽/бонус   ← бонусы не обесцениваются полностью
Верхний порог = 0.20 ₽/бонус   ← защита первых месяцев с малой эмиссией
```

**Почему сглаживание, а не прямой пересчёт:**
Сырой ежемесячный пересчёт создаёт волатильность — при вирусном росте в январе курс обвалится в феврале. Сглаживание делает изменения плавными: пользователь не видит резких сдвигов.

**Пересмотр:** 1-е число каждого месяца. На UI: «Курс на июнь: 0.1 ₽/бонус. Пересматривается 1 июля. Возможное изменение к 1 июля: ±30%.»

### Минимальный гарантированный курс

Курс не падает ниже **0.01 ₽/бонус** без явного решения пилота. Это абсолютная гарантия — даже при многократном падении эмиссии курс не опустится ниже этой планки.

<summary><b>10. Баллы → Бонусы</b></summary>

Баллы и бонусы — разные объекты учёта. Бонусы рассчитываются ежедневно на основе активности с учётом суточного лимита и накапливаются на бонусном балансе.

```
Бонусы за день      = min(Итоговые_баллы_за_день, суточный лимит начислений)
Баланс бонусов     += Бонусы за день
```

При оплате:
```
Скидка (₽) = Баланс бонусов × Курс
```

**Скидка не ограничивается** процентом подписки. Пилот может полностью покрыть стоимость подписки бонусами, если их хватит.

**На что тратятся бонусы:** подписка, семинары, потоки с наставниками, курсы на платформе. Механизм один и тот же — бонусный баланс списывается при любой оплате.

**Накопление без потолка:** неиспользованный остаток бонусов переходит на следующий месяц **для всех ступеней** (в v4.2 это работало только для Мастера+). Никаких ограничений на верхний лимит баланса — пилот волен копить столько, сколько хочет, и тратить когда удобно. Это в духе принципа П7 «накопление, не сгорание».

В v4.2 действовали отдельные месячные лимиты на пользователя и потолки скидки от стоимости заказа (30%/50%/100% в зависимости от тира). В v4.3 эти ограничения упразднены — единый механизм для всех ступеней.

</details>

<summary><b>11. Реферальная программа</b></summary>

Реферальные выплаты пропорциональны входящей выручке от приведённых подписчиков. Это самофинансирующийся механизм: каждый платёж приведённого пилота автоматически порождает реферальный бонус для реферера. Чем больше людей приходит и платит — тем больше реферальных бонусов, и тем выше входящая выручка. Программа балансируется сама.

| Событие | Что получает пилот |
|---|---|
| Реферал зарегистрирован | На запуске не даёт баллов (защита от абуза). Будет включено позже — см. §6.5 |
| Реферал оплатил подписку | Бонусы из реферальной части бюджета: бонусы = сумма_платежа × реферальная_ставка / курс |

**Пример:** друг оплатил 1 000 ₽, реферальная ставка = 10%, курс = 0.1:
```
Реферальные бонусы = 1 000 × 0.10 / 0.1 = 1 000 бонусов = 100 ₽ для реферера
```

**Дополнительная защита от абуза (роадмап):** реферал засчитывается окончательно после удержания подписки минимум 1 месяц.

В v4.2 при курсе 0.05 та же ситуация давала вдвое больше бонусов количественно — но в рублях это была та же благодарность. Удвоение курса при сокращении количества бонусов даёт ту же рублёвую ценность.

</details>

Корректный пересчёт под другую ступень и страйк: сначала снимаем базовый множитель из «эффективных» (`вес = эффективные / 1.3`), затем умножаем на актуальные коэффициенты. Для Мастера со страйком 28+ дней совокупный множитель: ×3.5 × ×2.2 ÷ 1.3 ≈ **×5.92** от «эффективных» из таблицы §6.

| Знание извлечено | 1 | 44.2 | 44.2 × 5.92 ≈ 262 | 262 |
| Комментарий в клубе | 2 | 5.2 | 5.2 × 5.92 ≈ 31 | 62 |
| **Сумма свободная** | | | | **~1 016** |
| Дневной лимит действия | | | 70 (для Мастера) | каждое действие срезается до 70 |
| Суточный лимит | | | 70 × 8 = **560** | сумма за день режется до 560 |
| **Зачёт за день** | | | | **560** (лимит срабатывает) |
| **За 20 активных дней** | | | | **11 200 бонусов = 1 120 ₽** |

Накопленные бонусы 1 120 ₽ > 1 000 ₽ → подписка полностью закрыта, остаток (~120 ₽) переносится на следующий месяц. Если Мастер копит бонусы несколько месяцев — баланс растёт без верхнего лимита, и в нужный момент пилот может оплатить им большой семинар, курс или несколько месяцев подписки разом.

> **Что нужно для бесплатной подписки на ступенях 5–9:** ритм ~30% суточного лимита 20 дней в месяц + Систематический/Дисциплинированный = ~600–800 бонусов/мес → 60–80 ₽/мес. На таких ступенях бесплатная подписка набирается за 12–15 месяцев. На ступенях 10–12 — за один-два месяца интенсивной работы.

<summary><b>15. Открытые вопросы для обсуждения</b></summary>

1. **Калибровка после первого месяца** реальных данных: пересмотр базового множителя, калибровочного множителя и коэффициентов Квалификации по результатам.

2. **Группа 4 при росте N:** события Сообщества (коэф. группы = 4) умножают вес на 4; при большом комьюнити эмиссия по G4 может превысить расчётную. Мониторить отдельно.

3. **Включение отложенных событий (§6.5):** какие из 16 типов событий вернуть в активный пул и в какой последовательности? Каждое — отдельное решение через ArchGate с обоснованием антинакрутки.

4. **Маршрут от Случайного к Практикующему.** Случайный получает 0 баллов. Что в UI показывает «как стать Практикующим»? Это домен Диагноста — нужно интегрировать в общий UX лояльности.

5. **Прогресс-бар «до бесплатной подписки» — формула пути.** Как считать «осталось X ₽» для разных ступеней? Подсказка: «Сделать 2 урока + 1 пост — получишь Y ₽».

6. **Мотивационный слой «причастности»** — в v4.3 пока слабый. Перспектива: групповые вызовы с дополнительным бонусом за коллективное достижение (вне текущего scope).
