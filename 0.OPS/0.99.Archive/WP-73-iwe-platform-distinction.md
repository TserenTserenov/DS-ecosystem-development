# Различение: Платформа Aisystant ≠ IWE

**IWE** — система организации интеллектуальной работы. Пользователь применяет её в своей рабочей среде (редактор, Git, заметки). Подключается к Платформе Aisystant через MCP Gateway для получения сервисов. Базовые функции работают без подключения.

**Платформа Aisystant** — облачный бэкенд, единый для всех пользователей. Доставляет контент, идентификацию, сервисы сообщества, прогресс.

**Это два разных объекта с явным интерфейсом между ними** (MCP Gateway `mcp.aisystant.com/mcp`).

## Personal Knowledge MCP — индексация личных репо

> Реализованный обходной путь для «❌ Запись в git-репо пользователя» из таблицы выше — без нарушения принципа data sovereignty.

Данные участника лежат в его GitHub-репо (он контролирует), платформа хранит только эмбеддинги. Запись из любого AI-клиента, подключённого к MCP Gateway (claude.ai, ChatGPT, VS Code), идёт через write tool → GitHub App «Aisystant Knowledge» коммитит файл в репо пилота → push → webhook → платформа автоматически переиндексирует изменённые файлы в эмбеддинги. Никаких ручных шагов: запись и индексация — один атомарный шаг для пользователя.

**Почему это совместимо с data sovereignty:** платформа не имеет прямого git-доступа. GitHub App действует от имени пользователя (Installation Token, OAuth-разрешение можно отозвать в любой момент). Сами данные лежат на GitHub у пользователя; платформа хранит только производные эмбеддинги для поиска.

Реализовано WP-187 (Gateway v2.0.0, апр 2026). Подробно → [WP-74 §SC-17 «IWE как сервис»](WP-74-platform-concept-of-use.md).

## Уточнение: Push-модель данных и Embeddings (2026-05-31)

> **Источник:** Оперативка ИТ 2026-05-31, п.4 повестки.

### Ключевой принцип: данные идут из IWE → в Платформу (не наоборот)

**Embeddings рабочего пространства** (индекс файлов, контекст репо, локальная память) — это часть IWE, а не платформенный сервис. Платформа НЕ имеет доступа к репозиторию пользователя и не индексирует его самостоятельно.

Модель: **IWE → push → Платформа**. Платформа ждёт данных, не тянет их.

| Вопрос | Ответ |
|---|---|
| Где хранятся embeddings рабочего пространства? | На стороне IWE (Vault IWE — файловая система / basic-memory) |
| Как попадают на платформу? | IWE / IDE-клиент сам отправляет (push), не платформа тянет |
| Cursor, JetBrains и другие IDE? | Каждый IDE-клиент должен иметь собственный адаптер для push |
| Платформа читает из Git-репо напрямую? | НЕТ — нарушение data sovereignty (❌ в таблице выше) |

### Связь с концепцией Vault (Волт)

**Vault** — любое хранилище с интерфейсом read/write/find, привязанное к проекту/команде (не к пользователю). Embeddings рабочего пространства = Vault IWE. Pack = один специализированный тип Vault.

Адаптер basic-memory MCP уже существует и реализует этот интерфейс. Formal ArchGate + РП «Дизайн Vault-адаптера» — запланированы на W23 (см. `DS-my-strategy/docs/vault-intent-2026-05-31.md`).
