## Уровень 1. БД и события (2–4 часа)

### Задача 1.1 — Проверить интеграцию оплат → подписки

Запустить в Neon Console:
```sql
-- БД subscription
SELECT status, source, count(*) 
FROM public.contract 
GROUP BY status, source;

-- БД learning
SELECT event_type, count(*), max(occurred_at) as last
FROM public.domain_event
WHERE event_type IN ('payment_received', 'subscription_granted')
GROUP BY event_type;
```

**Что проверить:** сколько `payment_received` vs `subscription_granted`, есть ли контракты с `source='native'`.

**Что изучишь:** EDA, 3 БД (payment, learning, subscription), projection-worker, цепочка событий.

### Задача 1.2 — Проверить feature flags

- Посмотреть в БД `reference` таблицу `feature_flags`
- Узнать, какие фичи включены, какие выключены
- Найти в коде бота или gateway, как они читаются

**Что изучишь:** reference БД, конфигурация без перезапуска, связь данных и кода.

## Уровень 2. Код и реальные фичи (4–8 часов)

### Задача 2.1 — История проверок в чекере

- В боте добавить кнопку «история проверок» рядом с «проверить»
- Если по этому ответу уже был запрос — показать предыдущий результат, не делать новый запрос к LLM
- Сохранить историю в соответствующей БД

**Что изучишь:** бот-архитектура, кеширование, история взаимодействий, БД learning/persona.

### Задача 2.2 — Тип мероприятия у потока

- Добавить поле `event_type` (seminar / practicum / residency / workshop) в сущность потока
- Настроить, чтобы письма и сценарии оплаты подтягивались по типу
- Для марафона — включить упрощённую оплату (ссылка на привязку в письме)

**Что изучишь:** LMS-схема, шаблонизация писем, сценарии оплаты, типизация.

### Задача 2.3 — Страница «купить» для марафона

- Добавить на лендинг программы кнопку «купить» с ссылкой на оплату
- Проверить, что после оплаты приходит письмо со ссылкой на группу

**Что изучишь:** витрина, платёжный цикл, интеграция бот-сайт, YooKassa-вебхуки.

## Уровень 3. Погружение в архитектуру (8–16 часов)

### Задача 3.1 — Навигация в гайде

- Добавить кнопки «вперёд / назад» в guide.system-school.ru
- Проверить, что навигация работает с ORY-сессией

**Что изучишь:** фронтенд, статические сайты, аутентификация Ory, сессии.

### Задача 3.2 — Страница статуса сервисов (табло доступности)

- Сделать простую страницу на поддомене (например, `health.aisystant.ru`)
- Вывести статусы ключевых сервисов (бот, LMS, MCP, gateway)
- Можно на основе Better Stack API или своих проб

**Что изучишь:** интеграция с внешними API, деплой на Railway/CF Workers, публичные страницы, probes.

### Задача 3.3 — Парсер: простые поправки

- Разобрать накопленные задачи от пользователей
- Отсортировать по сложности (quick win vs нужен research)
- Сделать 3–5 простых правок

**Что изучишь:** кодовая база, процесс приёма правок, тестирование, git-flow.
