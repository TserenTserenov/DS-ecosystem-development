## 0. Критерий-классификатор (Wave 3, операционный)

| № | Признак | Принадлежит |
|---|---------|-------------|
| 1 | Каноническое знание (паки, руководства, методологические определения), данные/память пользователей | **Платформа** (Aisystant / MIM) |
| 2 | API/сервисы, независимые от конкретного клиента (assistant-agnostic) | **Платформа** |
| 3 | Нумерация доменных ID (DP.SC.NNN, DP.IWE.NNN и т.д.) и реестры | **Платформа** |
| 4 | Инструкции среды (CLAUDE.md, правила, хуки, скрипты, update.sh) | **IWE/клиент** — дистрибутив рабочей среды |
| 5 | Параметры конфигурации экземпляра (`IWE_ORIGIN_LANG`, `IWE_PRODUCT_ORG`, params.yaml, org-refs) | **IWE/клиент** |
| 6 | Переводы текстов среды (шаблон/скиллы/правила RU→EN) | **IWE/клиент** — продуктовая ветка iwesys |
| 7 | Оговорка DP.D.095 v2: управляет пользователем → IWE; управляет платформой → Платформа; **владение каноном ≠ управление локальной копией** | Критерий-разграничитель для пограничных случаев |

**Пограничное (выносить на решение пилота):**
- «Методология IWE» / «структурирование базы знаний» — описывает методы работы в среде, но методологический канон может принадлежать платформе
- «Персональные руководства» — генерятся платформой (Портной), но доставляются в репо пользователя

**Файл:** `PACK-digital-platform/pack/digital-platform/02-domain-entities/DP.D.095-iwe-vs-platform-boundary.md`

**Предлагаемая правка** — добавить абзац после таблицы:

```markdown
Тест: «Если платформа изменит этот Pack — мой экземпляр обновится через update.sh?» Да → канон платформенный.
```

**Статус:** `ready` — 1-2 строки, не меняет основной критерий, только добавляет оговорку.

## 4. Г-минимум — IntegrationGate (только проектная часть)

### 4.1 Обещание (Service Clause)

**Предлагаемый DP.SC.NNN — Реестр нумераций IWE:**

```
Триггер: файл в репо затрагивает идентификатор (DP.NNN, DP.SC.NNN, DP.IWE.NNN, AR.NNN и т.д.)
Вход: идентификатор кандидата
Выход: статус — OK / Case B (коллизия с другим пространством) / Case C (нет в реестре)
Инвариант: один идентификатор — одна запись в реестре; пространства имён изолированы
Режим отказа: Case B/C блокируют commit через pre-commit хук (после разрешения пилота, S-33)
Время отклика: синхронно в момент commit
```

### 4.2 Сценарии использования (минимум 3)

1. **Разработчик создаёт новый SC** → реестр проверяет: нет ли уже `DP.SC.NNN` с таким N → OK или Case B (дублирующий номер в другом пространстве)
2. **Агент создаёт файл с AR.NNN** → реестр проверяет: N не занят в диапазоне AR → OK или Case C (AR.500 не существует в реестре, не зарегистрировано)
3. **Орг-миграция репо** → реестр обнаруживает, что репо из личного аккаунта переходит в `iwesys`, где уже есть файл с тем же DP.SC.NNN → Case B (коллизия пространств)

### 4.3 Роль (заготовка)

**Предлагаемая DP.ROLE.NNN — Регистратор нумераций:**
```
Обязанности: хранить скелет реестра (~15 namespace одной строкой); отвечать на запрос
  «существует ли N в пространстве X?»; регистрировать новые ID.
Полномочия: read-only к репо; write только в реестр.
Связи: вызывается из pre-commit хука (AR.234-enforcement); вызывает детектор Case B/C.
Входы: (namespace, id) → статус
Выходы: OK | Case B (коллизия) | Case C (не зарегистрирован)
```

**Скелет реестра (~15 namespace, одна строка каждый):**
```yaml
namespaces:
  DP.SC: {owner: PACK-digital-platform, range: 001-999, registered: [001..230]}
  DP.IWE: {owner: PACK-digital-platform, range: 001-099, registered: [001..011]}
  DP.ROLE: {owner: PACK-digital-platform, range: 001-099, registered: [001..070]}
  DP.ARCH: {owner: PACK-digital-platform, range: 001-020, registered: [001..006]}
  DP.D: {owner: PACK-digital-platform, range: 001-200, registered: [001..132]}
  AR: {owner: PACK-agent-rules, range: 001-499, registered: [001..234]}
  MIM.R: {owner: PACK-MIM, range: 001-099, registered: [001..009]}
  PD.FORM: {owner: PACK-personal, range: 001-200, registered: [001..137]}
  VR.R: {owner: PACK-agent-rules, range: 001-010, registered: [001..002]}
  DP.METHOD: {owner: PACK-digital-platform, range: 001-050, registered: []}
  DP.WP: {owner: PACK-digital-platform, range: 001-099, registered: []}
  MAP: {owner: PACK-digital-platform, range: 001-010, registered: [001..002]}
  DP.CONCEPT: {owner: PACK-digital-platform, range: 001-010, registered: [001..003]}
  LS.FORM: {owner: PACK-language-style, range: 001-010, registered: [001]}
```
