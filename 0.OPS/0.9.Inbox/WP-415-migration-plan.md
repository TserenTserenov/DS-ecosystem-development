# План миграции репозиториев по организациям (WP-415)

> **Статус: РЕКОМЕНДАЦИЯ к обсуждению.** Исполнение (перенос/создание орг) — необратимое архитектурное действие → перед стартом ArchGate + ратификация с Андреем/Решатом. Источник модели: концепция `WP-415-russia-world-split-concept.md` §1a/§1b + блок «Топология платформ + порядок миграции».

## Поправка к premise

«Перенести всё русское из `aisystant` в `mimsys`» — неточно по двум причинам:

1. **В `aisystant` сейчас всего 4 репо** (сверка `git remote` 13 июня): `PACK-personal`, `DS-ecosystem-development`, `DS-principles-curriculum`, `docs`. Основной канон знания (паки) лежит под личным аккаунтом `TserenTserenov`. Реальная миграция = консолидация канона из **личного + aisystant** в `mimsys`, не только из aisystant.
2. **Не всё едет в `mimsys`.** По юрисдикции делим только **канон знания** (паки). Продукт → `iwesys`; руководства → гайд-орги; личное/секреты/governance → остаются. «Русское» ≠ «в mimsys».

## Целевые дома (куда что)

> **⚠️ Скорректировано принципом независимости 5a (директива пилота 13 июня):** канон знания НЕ переносим в `mimsys` (это сделало бы мир зависимым от России). Канон-источник = **мировой контур**; `mimsys` = downstream-проекция + персональные данные россиян.

| Категория | Дом | Содержит |
|-----------|-----|----------|
| Канон знания (source-of-truth) | **`aisystant`** (под Aisystant Corp) | Паки (онтология/методы), руководства-источники — владение Aisystant Corp, язык контента любой |

## Порядок действий (sequencing)

1. **Предусловие:** мировое юрлицо — **Aisystant Corp** (ратифицировано 14 июня) — оформлено и владеет мировыми орг/инфрой. Юридическое оформление Aisystant Corp — за Андреем/Решатом + юристом.
2. **Ратификация модели** — **принята** (14 июня): топология орг + принцип независимости 5a + дом канона `aisystant` (§1c). Остаётся юридическое оформление Aisystant Corp.
3. **ArchGate** на миграцию (необратимое архитектурное действие): профиль ЭМОГССБ, в т.ч. тест разрываемости.
4. **Создать организации:** `mimsys`, `mim-guides`, `aisystant-guides` (проверить занятость имён). `iwesys` уже создан.
5. **Сверка с Track B** (WP-285): Паша уже создал отдельную орг под инфру Track B (`gcp-infrastructure`) — не пересекается ли со счётом орг? Уточнить до создания.
6. **Консолидировать канон-источник в мировом контуре** (паки из чёткого списка) → мировая канон-орг (GitHub transfer, по одному, с редиректом). `PACK-personal` уже в мировом aisystant. После каждого: переклонить локально, обновить cross-ссылки + конфиг индексации платформы.
7. **Настроить односторонний поток** проекции канона мир→`mimsys` (русская раздача). Мир из России не читает.
8. **Руководства:** источник в мировом контуре; русская проекция → `mim-guides`, английская витрина → `aisystant-guides`.
9. **Решить граничные случаи** (таблица выше) → разместить по решению.
10. **Тест разрываемости:** отключить `mimsys` в стейджинге → мировой продукт работает. Только после «да» — дальше.
11. **Продукт в `iwesys`** (Шаблон/шлюз/s2r) — по сигналу «переноси»; параметризация + конвейер текстов среды.
12. **Публичный запуск `iwesys`** — после готовности EN-ядра канона в мировом контуре.

## Стратегический вопрос — РЕШЁН принципом 5a

Где живёт source-of-truth канона и кто им владеет — **решено директивой пилота:** канон-источник в **мировом** контуре, владение мировым юрлицом; российская организация НЕ может быть домом источника знания (иначе мир зависит от России). Остаточный под-вопрос на ратификацию: конкретный мировой дом канона — `aisystant` или отдельная нейтральная канон-орг.

## Чего НЕ делаем сейчас

- Не создаём орги, не переносим репо (ждёт ратификации + ArchGate + мирового юрлица).
- Не переносим канон в `mimsys` (нарушает принцип независимости 5a).
- Не переименовываем `aisystant` (вариант 5 отклонён — рвёт бренд).
- Не переносим Шаблон в `iwesys` (ждёт «переноси»).
