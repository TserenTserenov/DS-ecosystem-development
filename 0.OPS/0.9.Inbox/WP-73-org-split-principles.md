# Принципы разделения Россия / Мир и конвейер управления организациями GitHub

> **Назначение.** Единый источник истины по разделению инфраструктуры, организаций GitHub, языков и финансовых потоков. Команда сверяется с этим файлом.
>
> **Статус:** черновик на ратификацию с Андреем и Решатом. После согласования — перенести в постоянный governance-дом.

<details open>
<summary><b>0. Главное за 30 секунд</b></summary>

- Три разные оси: **продукт** (Aisystant ≠ IWE), **рынок** (Россия ≠ мир), **владение** (личное ≠ организация). Их нельзя смешивать.
- Четыре «дома» на GitHub: `aisystant` (мировой дом, остаётся) · `iwe-platform` (продукт-методы IWE, имя на выбор) · `mim-school` (российская операция, имя на выбор) · личные пространства участников команды.
- **В организации `aisystant` — строго английский.** Не-английское → переводится, уезжает в другую орг, либо становится личным/закрытым.
- Каждый участник пишет на том языке, в котором думает быстрее. Английская версия собирается из этого материала пакетно — не при каждой правке и не в ущерб скорости работы автора.
- Жёсткое разделение финансов: мир платит иностранными картами, Россия — рублями. Наставники только в России.
- Перенос: сервисы да, данные пользователей нет (мир с нуля). При остановке — не удалять.

</details>

<details>
<summary><b>1. Топология организаций (4 дома)</b></summary>

| Дом | Что содержит | Язык | Аудитория | Видимость |
|-----|-------------|------|-----------|-----------|
| `aisystant` (есть, остаётся) | Мировой дом: платформа-продукт, витрина для инвесторов | строго английский | мир, инвесторы | публичная витрина |
| `iwe-platform` (новый, имя на выбор) | Продукт-методы IWE: движок, скиллы, протоколы, канонический набор паков | двуязычный канон | мир, сообщество | резерв → публичная |
| `mim-school` (новый, имя на выбор) | Российский рынок: наставники, рубли, экосистема, образовательный контент, внутренний governance | русский | Россия, команда | приватная |
| Личные пространства участников (`TserenTserenov` и др.) | Экзокортексы авторов, управляющие репо конвейера (concept-graph, style-base), рабочие черновики | русский | авторы и участники | приватная |

**Решения по оси:**
- **Продукт ≠ рынок ≠ владение.** Платформа Aisystant и IWE (набор методов) — разные продукты. Россия/мир — ось инфраструктуры и языка. Личное — экзокортекс, не продукт.
- **Мировой дом — `aisystant`** (<https://github.com/aisystant>). Остаётся, не переименовываем.
- **Россия — отдельная новая орг.** Имя `mim` занято сторонним лицом (не мы) → рабочее `mim-school`; свободны также `mim-systems`, `mim-edu`, `mim-academy`.
- **IWE — отдельная орг.** Имя `iwe` занято заброшенной орг (с 2018) → рабочее `iwe-platform`; свободны также `intellect-work`, `iwe-methods`, `iwe-env`, `iwe-hq`.
- **Финальные имена орг выбрать до первого наполнения** (переименование орг ломает все ссылки).
- **4-я «управляющая» организация не создаётся.** Управление кросс-орг синхронизацией = репозиторий + GitHub App, не отдельная орг.

</details>

<details>
<summary><b>2. Принцип языка</b></summary>

- **Каждый автор пишет на том языке, в котором думает.** Нет требования переключаться в момент написания. Сейчас для большей части команды это русский.
- **Английский — публикуемый снимок для мира.** Канон для международной аудитории и инвесторов. Синхронизируется пакетно (раз в спринт), НЕ при каждой правке.
- **Жёсткая связка русский↔английский — только для стабильного ядра** (граф понятий, ключевые гайды), не для всей базы знаний.
- **В `aisystant` — строго английский.** Не-английский материал: либо переводится, либо уезжает в `mim-school`, либо становится личным/закрытым.
- **Канон двуязычен, витрина одноязычна и производная.** Витринные репо (`aisystant/docs`, `iwe/README`) содержат только английские проекции, сгенерированные из канона.

Отвергнуто: (а) двуязычная связка на каждой единице знания с подтверждением перевода per-commit — блокирует автора; (б) полный автоперевод на лету — смысл поплывёт.

</details>

<details>
<summary><b>3. Финансы и потоки оплат</b></summary>

- **Жёсткое разделение финансов и потоков оплат:** рубли в России, иностранные карты в мире. Зеркальная асимметрия принята осознанно.
- **Наставники только в России.** Мир пока только самостоятельное прохождение. Хочешь наставника — платишь в `mim-school` (рубли, российский контур).
- **Мирового продукта «с наставником» пока не существует.**
- **Российская инфраструктура НЕ оформляется под Aisystant** (юридические и репутационные риски совместного владения).

</details>

<details>
<summary><b>4. Инфраструктура и перенос</b></summary>

- **Переносим сервисы, не данные пользователей.** Мир стартует с нуля; перенос данных — экспортом по желанию пользователя.
- **При остановке сервисов не удалять**, держать в архиве несколько месяцев для восстановления.
- **Приоритет переноса** — сервисы на иностранной инфраструктуре (умный поиск/Ultra, телеграм-сервисы).
- **Российская инфраструктура физически не в России** (Telegram заблокирован → бот не работает в России). Хостинг для российского контура выбирается отдельно; решают Церен + Ильшат + Андрей совместно.
- **Для российского контура:** OpenAI заблокирован → использовать провайдеров без ограничений в РФ (DeepSeek, Qwen, OpenRouter).
- **Шлюз — чистый маршрутизатор** (только URL бэкендов), вся прикладная логика в MCP-серверах.

</details>

<details>
<summary><b>5. Поток разработки и передачи между контурами</b></summary>

Три контура разработки в команде. Каждый принимает результат предыдущего и разворачивает дальше.

**Церен — разработка и MVP.**
Создаёт новую архитектуру, добавляет функциональность, доводит до работающего MVP. Примеры текущей работы: пилот с Наташей (страница персонального руководства), инфраструктура управления организациями на GitHub. Работает в своём окружении, фиксирует решения в governance-репо команды.

**Андрей — мировой контур.**
Принимает MVP от Церена, добавляет свои доработки, разворачивает на мировой инфраструктуре. Инфраструктура мирового контура: Google Kubernetes Engine (GKE), развёрнут Пашей.

**Ильшат — российский контур.**
Принимает доработанный MVP с учётом вклада всей команды, соблюдает текущую архитектуру, разворачивает на российской инфраструктуре. Инфраструктура российского контура: VK Cloud, развёрнут Пашей.

Паша готовит обе инфраструктурные площадки (GKE и VK) и поддерживает их работоспособность.

</details>

<details>
<summary><b>6. Конвейер перевода: граф понятий + база стилей (общий принцип)</b></summary>

> **Общий принцип синхронизации:**
> **Один канон на единицу знания. Язык, аудитория и площадка — проекции канона, не его копии.**

- **Единица знания** (понятие, документ, гайд) имеет одно каноническое представление.
- **Граф понятий** — словарь переводных связей для языковой проекции (русско-английский, жёсткие связки терминов).
- **База стилей** (разговорный / программистский / для детей / для инвесторов) — трансформ под регистр и аудиторию. Частично существует.
- **Конвейер** рендерит проекции (русское репо, английское репо, сайт) из канона + граф + стиль. Не «на лету» — через ревью.
- **Изменение понятия → импакт-анализ по графу.** Сценарий: меняется ключевой термин в базе понятий. Конвейер обходит обратные ссылки, находит все затронутые места, предлагает сгруппированные типовые замены на подтверждение. Не автозамена (риск ложных срабатываний в чужих контекстах).

</details>

<details>
<summary><b>8. Домены и шлюзы</b></summary>

- Два шлюза: новый для мира, старый для России. Оба проксируют одни и те же MCP-серверы, но через разные Ory (международная vs российская).
- **Мир:** `mcp.assistant.com` (или временно `mcp2`/`world.assistant.com`). Всё в домене `assistant.com` ходит только через международную Ory, никогда в Россию.
- **Россия:** отдельный домен (`mcp.mim.com` или `system.ru`), российская Ory.
- Технический нюанс: один домен обслуживается одним сервисом. `assistant.com/mcp` (через хаки маршрутизации) возможно, но не рекомендуется — забудется, сломается. Лучше поддомен.
- Префикс `mcp.` функциональный (протокол MCP может смениться). Для мира допустимо нейтральное имя (`world.assistant.com`).
- MCP-серверы при переносе НЕ должны авторизоваться через старую Ory + старый домен.

</details>

<details>
<summary><b>9. Архитектурный чертёж конвейера (фиксируется ДО ручного переноса)</b></summary>

> **Зачем.** Без чертежа ручной перенос = случайное блуждание, и каждый файл придётся тащить дважды. Чертёж = соглашения, не код.

1. **Структура двуязычной единицы:** директория с `ru.md` + `en.md` + `meta.yaml` (статус синка, hash источника, дата снимка). EN помечается `synced_from_ru_at` + `source_hash` — видно, когда английский отстал. Применяется ТОЛЬКО к каноническим репо в `iwe`. Витринные репо потребляют готовые EN-проекции.
2. **Naming convention:** имя репо без языкового суффикса (язык внутри файлов). Витринные EN-only репо помечаются флагом `lang: en` в корневом manifest.
3. **Граф понятий:** отдельный репо `concept-graph` (узлы: понятие RU + EN + определение; рёбра: связи и переводные пары). Источник для импакт-анализа.
4. **База стилей:** репо `style-base` (регистры как трансформы). Частично существует.
5. **Метаданные синка:** в каждом репо manifest `iwe-sync.yaml` (откуда канон, какие проекции, политика синка per-sprint/per-commit).
6. **GitHub App:** регистрируется однократно, устанавливается отдельно в каждой орг (`aisystant`, `iwe`, `mim`). Токен доступа выдаётся per-орг (JWT + installation ID). Единого кросс-орг токена не существует. Управление доступом = управление installations + секреты per org.
7. **Управляющие репо** (`concept-graph`, `style-base`) приватны в личном пространстве до операционализации `iwe`, затем мигрируют в `iwe` как публичные (сообщество контрибьютит термины и регистры). Секреты и токены App остаются в личном пространстве всегда.

</details>

<details>
<summary><b>10. Последовательность реализации</b></summary>

Переавтоматизация убивает процесс. Раскатывать постепенно, «попробовать и посмотреть».

**Критерий разделения:**
- **Фаза А** = репо, которые (а) образуют **внешний периметр** (видимы инвесторам/пользователям) И (б) **уже англоязычны** или требуют ≤1 спринта ручного перевода.
- **Фаза Б** = репо (а) **внутренние** ИЛИ (б) требующие существенной двуязычной структуризации.

**Фазы:**
- **Фаза А (сейчас, ручная):** чертёж конвейера (раздел 8) + этот файл принципов + табло. Перенос шлюза + 5 MCP по принципу «в Aisystant только английский».
- **Фаза Б (средний срок, полуручная):** граф понятий + база стилей как репозитории, ручной импакт-анализ, перенос репо по табло.
- **Фаза В (долгий срок, авто):** движок конвейера перевода + GitHub App, автоматический импакт-анализ.

</details>

<summary><b>11. Открытые вопросы (на ратификацию)</b></summary>

Россия: свободны `mim-school`, `mim-systems`, `mim-edu`, `mim-academy` (голый `mim` занят частным лицом, `mimeco` занят компанией MimeCo). Выбрать до первого наполнения орг.

- **Отдельная орг для России** — обсудить с Решатом (в отъезде); туда постепенно переносить русскоязычные репозитории.
- **Точная постоянная папка для этого файла** после ратификации — согласовать с командой.
- **Подмножество ADR из `DS-ecosystem-development`, релевантное миру** — как проецировать в английскую витрину.
