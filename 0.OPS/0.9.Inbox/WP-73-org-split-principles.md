# Принципы разделения Россия / Мир и конвейер управления организациями GitHub

> **Назначение.** Единый источник истины для решений-принципов по разделению инфраструктуры, организаций GitHub, языков и финансовых потоков. Команда сверяется с этим файлом. Собран по итогам ИТ-встреч с архитектором (4/7/9/11 июня) и пир-сессии Claude+Kimi (WP-415).
>
> **Статус:** черновик на ратификацию. После согласования с Андреем и Решатом — промоция в постоянный governance-дом по карте маршрутизации (DP.KR.001 §5).

<details open>
<summary><b>0. Главное за 30 секунд</b></summary>

- Три разные оси: **продукт** (Aisystant ≠ IWE), **рынок** (Россия ≠ мир), **владение** (личное ≠ организация). Их нельзя смешивать.
- Четыре «дома» на GitHub: `aisystant` (английская витрина) · `iwe` (продукт-методы, резерв) · `mim` (российская операция) · `TserenTserenov` (личное + управляющее пространство).
- **В организации `aisystant` — строго английский.** Не-английское → переводится, уезжает в другую орг, либо становится личным.
- Русский — рабочий черновик (пишется свободно). Английский — публикуемый снимок (синхронизируется пакетно, не блокирует автора).
- Жёсткое разделение финансов: мир платит иностранными картами, Россия — рублями. Наставники только в России.
- Перенос: сервисы да, данные пользователей нет (мир с нуля). При остановке — не удалять.

</details>

<details>
<summary><b>1. Топология организаций (4 дома)</b></summary>

| Дом | Что содержит | Язык | Аудитория | Видимость |
|-----|-------------|------|-----------|-----------|
| `aisystant` (есть) | Платформа-продукт для мира, витрина для инвесторов | строго английский | мир, инвесторы | публичная витрина |
| `iwe` (новый, резерв) | Продукт-методы IWE: движок, скиллы, протоколы, канонический набор паков | двуязычный канон | мир, сообщество | резерв → публичная |
| `mim` (новый) | Российский рынок: наставники, рубли, экосистема, образовательный контент, внутренний governance | русский | Россия, команда | приватная |
| `TserenTserenov` (личное) | Экзокортекс автора + управляющее пространство конвейера | русский | автор | приватная |

**Решения по оси:**
- **Продукт ≠ рынок ≠ владение.** Платформа Aisystant и IWE (набор методов) — разные продукты (вывод Андрея, 7 июня). Россия/мир — ось инфраструктуры и языка. Личное — экзокортекс, не продукт.
- **`iwe` создаётся сейчас как зарезервированный namespace** (пустая орг + 1-2 скелетных репо), наполняется позже. Имя GitHub дефицитно и необратимо; создать сейчас дешевле, чем делать re-branding после.
- **Имя мировой орг — решить позже.** Рабочее имя `iwe`, финальное выбрать перед публичным запуском (переименование орг ломает ссылки → до наполнения).
- **4-я «управляющая» организация НЕ создаётся.** Управление кросс-орг синхронизацией = репозиторий + GitHub App, не отдельная орг.

</details>

<details>
<summary><b>2. Принцип языка (русский черновик / английский снимок)</b></summary>

> **Решение пилота (11 июня, эскалация Кими).**

- **Русский = рабочий черновик.** Автор пишет свободно и быстро, владеет смыслом, не блокируется ожиданием перевода.
- **Английский = публикуемый снимок.** Канон для мира и инвесторов. Синхронизируется пакетно (раз в спринт), НЕ при каждой правке.
- **Жёсткая связка русский↔английский — только для стабильного ядра** (граф понятий, ключевые гайды), не для всей базы знаний.
- **В `aisystant` — строго английский** (принцип, ратифицирован 11 июня). Не-английский материал: либо переводится, либо уезжает в другую орг (`mim`), либо становится личным/закрытым.
- **Канон двуязычен, витрина одноязычна и derived.** Витринные репо (`aisystant/docs`, `iwe/README`) содержат только английские проекции, сгенерированные из канона.

Отвергнуто: (а) двуязычная связка на каждой единице знания с подтверждением перевода per-commit — блокирует автора, оверкил для команды из 4 человек; (б) полный автоперевод на лету — переведёт плохо, смысл поплывёт (возражение Андрея).

</details>

<details>
<summary><b>3. Финансы и потоки оплат</b></summary>

- **Жёсткое разделение финансов и потоков оплат:** рубли в России, иностранные карты в мире. Зеркальная асимметрия принята осознанно (иностранец с иностранной картой не может оплатить в российском контуре, как россиянин не может за границей).
- **Наставники только в России.** Мир пока только самостоятельное прохождение. Хочешь наставника — платишь в `mim` (рубли, российский контур).
- **Мирового продукта «с наставником» пока не существует.**
- **Российская инфраструктура НЕ оформляется под Aisystant** (юридические и репутационные риски совместного владения). Хостинг — под отдельной российской компанией (system-school / MIM).

</details>

<details>
<summary><b>4. Инфраструктура и перенос</b></summary>

- **Переносим сервисы, не данные пользователей.** Мир стартует с нуля; перенос данных — экспортом по желанию пользователя.
- **При остановке сервисов не удалять**, держать в архиве несколько месяцев для восстановления.
- **Приоритет переноса** — сервисы на иностранной инфраструктуре (умный поиск/Ultra, телеграм-сервисы).
- **Российская инфраструктура физически не в России** (Telegram заблокирован → бот не работает в России). Хостинг для российского контура выбирается отдельно; первое решение — где он живёт (кандидаты: Google, иной хостинг). Решают Церен + Ильшат + Андрей совместно.
- **Эмбеддинги и умный поиск для России** — китайский вариант / OpenRouter (OpenAI заблокирован).
- **Шлюз — чистый маршрутизатор** (только URL бэкендов), вся прикладная логика в MCP-серверах.

</details>

<details>
<summary><b>5. Конвейер перевода: граф понятий + база стилей (общий принцип)</b></summary>

> **Общий принцип синхронизации (стержень):**
> **Один канон на единицу знания. Язык, аудитория и площадка — проекции канона, не его копии.**

- **Единица знания** (понятие, документ, гайд) имеет одно каноническое представление.
- **Граф понятий** (русско-английский, жёсткие связки терминов; Церен уже начал) — словарь переводных связей для языковой проекции.
- **База стилей** (разговорный / программистский / для детей / для инвесторов) — трансформ под регистр и аудиторию. Частично существует (база разговорного стиля, база инженерного стиля кода).
- **Конвейер** рендерит проекции (русское репо, английское репо, сайт, детская версия) из канона + граф + стиль. Не «на лету» — через ревью.
- **Изменение понятия → импакт-анализ по графу.** Сценарий: Левенчук меняет «роль» → «стейкхолдер» в FPF. Конвейер обходит обратные ссылки графа, находит все затронутые места, предлагает сгруппированные типовые замены на подтверждение. Не автозамена (риск ложных срабатываний в чужих контекстах).

</details>

<details>
<summary><b>7. Домены и шлюзы</b></summary>

- Два шлюза: новый для мира, старый для России. Оба проксируют одни и те же MCP-серверы, но через разные Ory (международная vs российская).
- **Мир:** `mcp.assistant.com` (или временно `mcp2`/`world.assistant.com`). Всё в домене `assistant.com` ходит только через международную Ory, никогда в Россию.
- **Россия:** отдельный домен (`mcp.mim.com` или `system.ru`), российская Ory.
- Технический нюанс: один домен обслуживается одним сервисом. `assistant.com/mcp` (через хаки маршрутизации) возможно, но не рекомендуется — забудется, сломается. Лучше поддомен.
- Префикс `mcp.` функциональный (протокол MCP может смениться). Для мира допустимо нейтральное имя (`world.assistant.com`).
- MCP-серверы при переносе НЕ должны авторизоваться через старую Ory + старый домен.

</details>

<details>
<summary><b>8. Архитектурный чертёж конвейера (фиксируется ДО ручного переноса)</b></summary>

> **Зачем.** Без чертежа ручной перенос = случайное блуждание, и каждый файл придётся тащить дважды. Чертёж = соглашения, не код.

1. **Структура двуязычной единицы:** директория с `ru.md` + `en.md` + `meta.yaml` (статус синка, hash источника, дата снимка). EN помечается `synced_from_ru_at` + `source_hash` — видно, когда английский отстал. Применяется ТОЛЬКО к каноническим репо в `iwe`. Витринные репо потребляют готовые EN-проекции.
2. **Naming convention:** имя репо без языкового суффикса (язык внутри файлов). Витринные EN-only репо помечаются флагом `lang: en` в корневом manifest.
3. **Граф понятий:** отдельный репо `concept-graph` (узлы: понятие RU + EN + определение; рёбра: связи и переводные пары). Источник для импакт-анализа.
4. **База стилей:** репо `style-base` (регистры как трансформы). Частично существует.
5. **Метаданные синка:** в каждом репо manifest `iwe-sync.yaml` (откуда канон, какие проекции, политика синка per-sprint/per-commit).
6. **GitHub App:** регистрируется однократно, устанавливается отдельно (installation) в `aisystant`, `iwe`, `mim`; access token выдаётся per-installation (JWT + installation ID). Единого кросс-орг токена не существует. Управление доступом = управление installations + секреты per org.
7. **Управляющие репо** (`concept-graph`, `style-base`) приватны в личном пространстве до операционализации `iwe`, затем мигрируют в `iwe` как публичные (сообщество контрибьютит термины и регистры). Секреты и токены App остаются в личном пространстве всегда.

</details>

<details>
<summary><b>9. Последовательность реализации и критерий фаз</b></summary>

> **Предупреждение пилота (11 июня):** переавтоматизация убивает процесс. Раскатывать постепенно, «попробовать и посмотреть».

**Критерий разделения:**
- **Фаза А** = репо, которые (а) образуют **внешний периметр** (видимы инвесторам/пользователям) И (б) **уже англоязычны** или требуют ≤1 спринта ручного перевода.
- **Фаза Б** = репо (а) **внутренние** ИЛИ (б) требующие существенной двуязычной структуризации.

**Фазы:**
- **Фаза А (сейчас, ручная):** чертёж конвейера (раздел 8) + этот файл принципов + табло. Перенос шлюза + 5 MCP по принципу «в Aisystant только английский». Простой чеклист.
- **Фаза Б (средний срок, полуручная):** граф понятий + база стилей как репозитории, ручной импакт-анализ, перенос репо по табло.
- **Фаза В (долгий срок, авто):** движок конвейера перевода + GitHub App, автоматический импакт-анализ.

</details>

<summary><b>10. Открытые вопросы (на ратификацию)</b></summary>

- **Финальное имя мировой орг IWE** — выбрать перед публичным запуском.
- **Где живёт российская инфраструктура** (не физически в России) — кандидаты Google / иной хостинг; решают Церен + Ильшат + Андрей. Андрей формулирует задачу + 3 варианта хостинга.
- **Российская компания** для оформления российского контура (system-school / MIM) — обсудить с Решатом (в отъезде по повестке военкомата).
- **Отдельная орг для MIM** — обсудить с Решатом; туда же постепенно переносить русскоязычные репозитории.
- **Точная папка/дом файла принципов после ратификации** — по карте маршрутизации DP.KR.001 §5.
- **Подмножество ADR из `DS-ecosystem-development`, релевантное миру** — как проецировать в английскую витрину.
