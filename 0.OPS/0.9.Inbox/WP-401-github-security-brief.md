# GitHub security brief

**Тип:** Предложение для техсовета (Ильшат, Церен)
**Цель:** Договориться о способе устранения трёх связанных уязвимостей в организации GitHub

---

## Проблема (по итогам аудита безопасности)

| Уязвимость | Что не так | Риск |
|---|---|---|
| **C1** | Платёжный код (реестр платежей) лежит на личном GitHub-аккаунте, а не в организации компании | 🔴 критический: компрометация одного личного аккаунта → доступ ко всем платёжным базам данных и токенам ботов |
| **C2** | Расширенное сканирование безопасности GitHub выключено на приватных репозиториях, где есть секреты | 🔴 критический: утечка секретов в истории коммитов; сканирование не включено ни на одном из 14 проверенных репозиториев |
| **C3** | Коммиты нигде не подписываются; нет защиты авторства при работе нескольких людей над одним репозиторием | 🔴 критический: подделка автора/истории; риск в цепочке поставок кода |

**Как связаны:** C1 → компрометация реестра платежей → обходит и C2 (сканирование), и C3 (подпись) → итоговая компрометация.

---

## Текущее состояние (по результатам аудита)

```
Сканирование секретов:        3 из 14 репозиториев
Сканирование уязвимостей:     5 из 14 репозиториев
Защита основной ветки:        2 из 14 репозиториев (только прод-ветки бота)
Автообновление зависимостей:  0 из 14 репозиториев
Подпись коммитов:             0 из 14 репозиториев
```

**Критические пробелы:**
- Реестр платежей (личный аккаунт): ни сканирования, ни защиты ветки, ни подписи
- Репозиторий миграций базы данных: сканирование не включено
- Локальный шлюз для разработки: сканирование не включено
- Требование подписи коммитов больше не действует по умолчанию

---

## Вариант устранения

### Вариант 1: Полное решение (рекомендуется)

**Этапы:**
1. **Перенести реестр платежей в организацию компании** (не личный аккаунт)
   - Перенести историю коммитов из личного репозитория в репозиторий организации
   - Обновить адрес репозитория в CI-пайплайнах (если есть)
   - Закрыть личный форк (заархивировать, не удалять)

2. **Включить расширенное сканирование безопасности для всех приватных репозиториев с секретами**
   - Репозитории: реестр платежей, репозиторий миграций базы данных, локальный шлюз для разработки, + список репозиториев по общим признакам
   - Включить: сканирование секретов (обязательно) + автообновление зависимостей (опционально, следующим шагом)
   - Стоимость: ~$27/месяц

3. **Требовать подписание коммитов на критичных ветках**
   - Правило: подпись коммитов локально + защита основной ветки с обязательной проверкой подписи
   - Обучение: разослать инструкцию разработчикам
   - Резервный вариант: утвердить отдельные ветки без подписей как исключение (нужно обоснование)

4. **Защита основной ветки** (связанная уязвимость)
   - Требования: 1 проверка (review) + подпись коммита + прохождение проверок
   - Исключения: очень активные репозитории — можно оставить требования на уровень ниже
   - ⚠️ **Обнаружено 2026-07-04:** правила защиты веток на приватных репозиториях не работают на бесплатном тарифном плане GitHub (баннер "won't be enforced until you move to GitHub Team"). Организация тоже на бесплатном плане (64 приватных репозитория). Значит правила защиты веток сейчас **не действуют** ни на один приватный репозиторий организации, включая два самых критичных сервиса (обработка событий и приём платежей). На публичных репозиториях правила уже работают.
   - **Нужно решение:** апгрейд организации на платный тариф GitHub Team (~$4/пользователь/мес × 11 = ~$44/мес) — единственный способ включить защиту на приватных репозиториях.

**Бюджет:** 4-6ч команде (перенос истории + настройка + обучение) + ежемесячная подписка при апгрейде тарифа

### Вариант 2: Минимальный (только сканирование)

- Оставить реестр платежей у пилота, но включить расширенное сканирование
- Требование подписей — отложить
- Защита основной ветки — минимум (только на главной ветке)

**Риск:** остаётся вектор компрометации личного аккаунта.

---

## Что куда входит

| Что | Кто делает | Статус |
|---|---|---|
| **Перенос реестра платежей** | Отдельная задача | Требует решения пилота |
| **Включить расширенное сканирование** | Отдельная задача или часть текущей работы по безопасности | Требует бюджета (~$27/мес) и согласия пилота |
| **Защита основной ветки** | Связанная задача | Может быть выполнено параллельно |
| **Подписание коммитов** | Отдельная задача + обучение | Нужна инструкция и время на распространение |

---

## Решение, необходимое пилоту

**Три вопроса:**

1. **Полное решение или минимум?**
   - ✅ Полное (перенос реестра платежей + сканирование + подпись)
   - ⚠️ Минимум (только сканирование на текущих местах)

2. **Если полное — делать одним пакетом задач или несколькими независимыми?**
   - Несколько отдельных задач (специализированные, чистые, раздельные бюджеты)
   - Один пакет с этапами (компактнее, но следующие шаги будут зависеть друг от друга)

3. **Сроки:**
   - Срочно — перенос + сканирование до конца недели
   - После текущих приоритетов — стандартный цикл, середина месяца

## Контакт

- **Для техсовета:** Ильшат (владелец GitHub, настройки безопасности)
- **Для согласования:** Пилот (бюджет, приоритет)
- **Выполнение:** Ильшат + команда (для сканирования, защиты веток) + разработчики (для подписей)
