# КР-8 — GitHub security brief

**Статус:** Узкий вопрос WP-458 (Волна 1, USER-действия пилота)  
**Тип:** Предложение для техсовета (Ильшат, Церен)  
**Цель:** Договориться о способе устранения трёх связанных уязвимостей CI/CD  

---

## Проблема (обнаружено в WP-458 Ф1)

| Уязвимость | Статус | Риск | Источник |
|---|---|---|---|
| **C1** | Платёжный код на личном GitHub-аккаунте (payment-registry) | 🔴 критический | Компрометация 1 аккаунта → дамп всех Neon-БД + бот-токены |
| **C2** | GitHub Advanced Security (GHAS) выключен на secret-чувствительных приватных репо | 🔴 критический | Утечка секретов в истории коммитов; сканирование 0 репо из 14 |
| **C3** | Коммиты нигде не подписываются (commit.gpgsign=false); нет защиты авторства при много-writer | 🔴 критический | Подделка автора/истории; риск в цепочке поставок |

**Взаимосвязь:** C1 → компрометация payment-registry → обход C2 (сканирование) + C3 (подпись) → финальная компрометация.

## Текущее состояние (по сканированию аудита WP-458)

```
Сканирование секретов:        3/14 репо     (secret-scanning enabled)
Сканирование уязвимостей:    5/14 репо     (SAST workflow)

Автообновление зависимостей: 0/14 репо     (Dependabot)
Подпись коммитов:            0/14 репо     (commit.gpgsign)
```

**Критические пробелы:**
- `payment-registry` (личный аккаунт): 0 из 3 (сканирование, branch protection, подпись)
- `neon-migrations`: 0 сканирования
- `iwe-local-gateway`: 0 сканирования
- Больше нет дефолтного требования подписи коммитов

## Вариант устранения (ARCHGATE + CHILD-WP)

### Вариант 1: Полная переносимость (рекомендуется)

**Этапы:**
1. **Перенос payment-registry в организацию `aisystant`** (не личный аккаунт)
   - `git push` истории из TserenTserenov/payment-registry → aisystant/payment-registry
   - Обновить origin в CI-пайплайнах (если есть)
   - Закрыть личный форк (archive, не delete)

2. **Включить GHAS для всех secret-чувствительных приватных репо (целый организация)**
   - Репозитории: payment-registry, neon-migrations, iwe-local-gateway, + список в `Security & Analysis` по тегам
   - Включить: Secret scanning (обязательно) + Dependabot (опционально, Волна 2)
   - Стоимость: ~$27/месяц (GitHub Advanced Security for Enterprise)

3. **Требовать подписание коммитов на критичных ветках**
   - Правило: `commit.gpgsign=true` (локально) + branch protection на `main` с требованием "Commit signature"
   - Обучение: Распространить инструкцию между разработчиками
   - Fallback: Утвердить ветки без подписей как исключение (нужно обоснование)

4. **Branch protection на main** (ВЫ-6, связанная уязвимость)
   - Требования: 1 review + commit signature + passing checks
   - Исключения: personal-dev-program-architecture (очень активный), можно оставить на уровень ниже
   - ⚠️ **Найдено 2026-07-04:** GitHub rulesets на приватных репо не работают на бесплатном плане (баннер "won't be enforced until you move to GitHub Team"). Проверено — организация `aisystant` тоже на free-плане (64 приватных репо). Значит правила защиты веток сейчас **не действуют** ни на один приватный репо организации, включая event-gateway и payment-receiver (самые критичные — КР-1, КР-2). На публичных репо (aist_bot, digital-twin-mcp, iwe-local-gateway) правила работают уже сейчас.
   - **Нужно решение:** апгрейд организации на GitHub Team (~$4/пользователь/мес × 11 = ~$44/мес) — единственный способ включить защиту на приватных репо.

**Бюджет:** 4-6ч команде (передача истории + настройка + обучение) + ежемесячная подписка GitHub Team при апгрейде

### Вариант 2: Минимальный (только сканирование)

- Оставить payment-registry у пилота, но включить GHAS
- Требование подписей — отложить на WP
- Branch protection — минимум (только на main)

**Риск:** Остаётся вектор компрометации личного аккаунта.
