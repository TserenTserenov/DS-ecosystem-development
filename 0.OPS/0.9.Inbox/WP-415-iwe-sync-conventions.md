# Соглашения конвейера синхронизации канон → проекции (iwe-sync conventions v1)

### 0. Главное за 30 секунд

- **Единица знания = пара файлов** `name.ru.md` (канон) + `name.en.md` (проекция). Папка-на-единицу — только для понятий, обросших спутниками (диаграммы, код, ≥2 регистра).
- **«Английский отстал» определяется отпечатком** русского тела (без служебной шапки), хранится во frontmatter `*.en.md`. Правка метаданных канона не вызывает ложную пересинхронизацию.
- **Словарь понятий** (`concept-graph`) хранит только пару «термин RU↔EN» + устойчивый `concept_id`. Документы ссылаются на `concept_id`, не наоборот.
- **Двигает синхронизацию приватное хранилище `iwe-sync`** с секретами и сценарием. Токены доступа к организациям берутся на каждый шаг заново (живут ~1 час).
- **Фаза А = этот документ + чек-лист ручных шагов + шаблоны.** Физический перенос — после создания организаций и выбора имён.

### 1. Структура двуязычной единицы знания

**Дефолт — пара файлов рядом:**
- `name.ru.md` — **канон**. Frontmatter = семантические метаданные (теги, статус, автор). **Без полей синхронизации.**
- `name.en.md` — **проекция**. Frontmatter = язык / аудитория / стиль **+** поля синхронизации: `source_hash_body`, `synced_at`, `style_applied`.

**Почему пара, а не папка-на-единицу (дефолт):** корпус IWE — плоские формализации-одиночки (`DP.FORM.NNN`, `PD.FORM.NNN`). 95% единиц никогда не обрастут спутниками. Дефолт «папка из 3 файлов» = самая дорогая миграция (сотни одиночек → сотни папок) ради редкого кейса.

**Папка-на-единицу — разрешённое исключение** для единиц, реально обросших спутниками:
```
concept/
├── ru.md          # канон
├── en.md          # проекция (sync-поля во frontmatter)
├── meta.yaml      # состояние оркестрации (для сложной единицы)
└── diagram.svg    # спутник
```
Конвейер опознаёт обе формы: плоская — по наличию `*.ru.md`; папочная — по наличию `ru.md` внутри директории.

**Целостность пары — инвариант + автопроверка (CI):**
- Переименование идёт через инструмент конвейера (переименует пару атомарно).
- CI-проверка: каждый `*.en.md` обязан иметь братский `*.ru.md`. Сирота-`*.en.md` = ошибка сборки.
- **`*.ru.md`-сирота — НЕ ошибка** (новый канон без ещё не собранной проекции легитимен). Проверка односторонняя.

**Витринные репо (EN-only, напр. `aisystant/docs`):** язык в суффиксе сохраняется всегда (`*.en.md`), даже если репо одноязычен. Manifest `lang: en` — дополнительный флаг repo-level роутинга, не замена суффиксу. Поведение конвейера единообразно: канон `*.ru.md`, проекция `*.en.md`.

### 2. Отпечаток источника (детекция «английский отстал»)

`source_hash_body` = `sha256(нормализованное тело ru.md)`. Хэшируется **только тело**, не frontmatter — правка тегов/даты канона не помечает проекцию устаревшей.

**Регламент нормализации (строго, любой раннер зовёт эту функцию, не свою):**
1. strip YAML-frontmatter (всё между первой парой `---`);
2. CRLF → LF;
3. rstrip каждой строки (убрать хвостовые пробелы);
4. схлопнуть 3+ подряд пустых строк → 1;
5. ровно один финальный `\n`.

`source_hash_body` и sync-поля живут во frontmatter `*.en.md`. Сам `*.en.md` НЕ хэшируется никогда. В папочной форме те же поля живут в `meta.yaml`; хэш так же считается от тела `ru.md`, `meta.yaml` из хэша исключён как управленческий артефакт.

**Эталонная реализация** прилагается шаблоном (раздел 7) — раннер обязан использовать её, чтобы хэши совпадали между машинами.

### 3. Граф понятий (concept-graph)

- **Узел графа** = `concept_id` (устойчивый) + пара `term_ru` ↔ `term_en` + однострочное глоссарийное определение. **Не** полная единица знания (иначе дублирование, нарушение OwnerIntegrity).
- **Инверсия зависимости:** граф не знает о файлах; файлы знают о графе. Документ ссылается на понятия через frontmatter `concepts: [cp.rhy, cp.wld, ...]`.
- **Обратный импакт-анализ** (раздел 6 принципов) строится индексацией frontmatter `concepts:` по всем репо, не обходом графа. Меняется термин → находим все файлы с этим `concept_id` → группируем типовые замены на подтверждение (не автозамена).
- **Видимость:** `concept-graph` публичен (сообщество контрибьютит термины). Секретов не содержит.

### 4. Раннер конвейера и токены доступа

- **Отдельное приватное хранилище `iwe-sync`** (не `concept-graph`, т.к. тот публичен по §10.7 принципов и не может держать секреты). Содержит: сценарий раннера (GitHub Action), App-секреты обеих организаций, карту маршрутизации канон→проекция. Остаётся приватным всегда.
- **GitHub App** регистрируется однократно, устанавливается отдельно в каждой орг (`aisystant`, IWE-орг, при нужде RU-орг). Единого кросс-орг токена не существует.
- **Токены — on-demand:** installation-токен живёт ~1 час. Раннер держит App JWT и запрашивает installation-токен **перед каждым шагом** (читает канон из IWE-орг → пишет витрину в `aisystant` = два разных токена за один прогон).
- **Шлюз (gateway) к этому не причастен** — он чистый маршрутизатор (только URL бэкендов, §4 принципов). Логика синхронизации в `iwe-sync`, не в шлюзе.
- **Фаза реализации раннера:** для Фазы Б достаточно Action в `iwe-sync`. Отдельный сервис оправдан только на Фазе В (очереди, webhook-оркестрация, интерактивный импакт-анализ).

### 5. Манифест репозитория (iwe-sync.yaml)

Каждое репо-проекция несёт корневой манифест `iwe-sync.yaml`:
```yaml
projected_from: <iwe-орг>/PACK-xxx   # откуда канон
lang: en                              # язык проекции
sync_policy: per-sprint               # per-sprint | per-commit
```
Канонические репо манифест синка не несут (они источник). Витринные EN-only репо помечаются `lang: en` для repo-level роутинга.

### 6. Чек-лист ручных шагов пилота (разблокирует Фазу Б)

Эти шаги peer-сессия закрыть не может — они требуют решений пилота и действий на github.com:

1. [ ] **Выбрать финальное имя IWE-орг** (свободны: `iwe-platform`, `intellect-work`, `iwe-methods`, `iwe-hq`; голый `iwe` занят заброшенной орг).
2. [ ] **Выбрать финальное имя RU-орг** (свободны: `mim-school`, `mim-systems`, `mim-edu`, `mim-academy`; `mim`/`mimeco` заняты).
3. [ ] **Создать обе организации вручную** на <https://github.com/account/organizations/new> (командной строкой нельзя).
4. [ ] **Выбрать видимость** репо при создании (канон IWE — публичный/резерв; RU — приватный).
5. [ ] **Создать приватный репо `iwe-sync`** под личным аккаунтом или в IWE-орг приватно.
6. [ ] **Зарегистрировать GitHub App** один раз, установить в обе орг.
7. [ ] **Положить App-секреты** в Actions-secrets репо `iwe-sync`.

После шагов 1-3 снимается блокировка `WP-412 Ф4б` (нужна созданная IWE-орг).

### 7. Шаблоны (заготовки для Фазы Б)

**Эталон нормализации тела (псевдокод раздела 2):**
```python
def normalize_body(text: str) -> str:
    # 1. strip YAML frontmatter
    if text.startswith("---"):
        end = text.find("\n---", 3)
        if end != -1:
            text = text[end + 4:]
    # 2. CRLF -> LF
    text = text.replace("\r\n", "\n").replace("\r", "\n")
    # 3. rstrip каждой строки
    lines = [ln.rstrip() for ln in text.split("\n")]
    text = "\n".join(lines)
    # 4. схлопнуть 3+ пустых строки -> 1
    while "\n\n\n" in text:
        text = text.replace("\n\n\n", "\n\n")
    # 5. ровно один финальный перевод строки
    return text.strip("\n") + "\n"
```

**Шаблон узла графа понятий:**
```yaml
concept_id: cp.rhy
term_ru: ритм
term_en: rhythm
gloss: "регулярность практики саморазвития"
```

**Шаблон манифеста проекции** — см. раздел 5.

**Шаблон frontmatter проекции `*.en.md`:**
```yaml
---
lang: en
style: default
source_hash_body: <sha256>
style_applied: default
---
```

### 8. Что НЕ входит в Фазу А

- Физический перенос репо по табло (раздел 7 принципов) — Фаза Б.
- Граф понятий и база стилей как наполненные репозитории — Фаза Б (зависит от `WP-412 Ф4а`: структура PACK-language-style).
- Движок конвейера перевода и автоматический импакт-анализ — Фаза В.
- Перенос шлюза + 5 MCP в `aisystant` — после создания орг (ручные шаги, раздел 6).
