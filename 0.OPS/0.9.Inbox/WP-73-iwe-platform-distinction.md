# Различение: Платформа Aisystant ≠ IWE

> **Статус решения:** принято на встрече 20 (24 мая 2026). Тсерен отвечает за IWE, Андрей — за платформу. Проектируются отдельно.

---

## 1. Почему вопрос возникает

Первоначальная позиция Тсерена (из транскрипта встречи):
> «Я вообще как бы считаю, что IWE — это как бы часть платформы.»

Эта позиция немедленно порождает противоречие: если IWE — часть платформы, то IWE обязательна для каждого пользователя платформы. Но это не так — пользователи T1–T3 работают через бот без VS Code и личного git. Значит, нужно другое разграничение.

---

## 2. Аналогии

### 2.1. Смартфон и Apple — различение «устройство ≠ экосистема»

Тсерен, транскрипт встречи 20:
> «Вот как бы у меня есть смартфон там, с приложениями Apple и так далее. Вот это вроде смартфон мой. Смартфон — часть платформы Apple или нет? Ну, скорее, наверное, **нет**. Это какая-то штука, которая базируется на этой платформе. И получается, платформа мне постоянно **что-то доставляет**.»

**Маппинг:**

| Apple | Aisystant |
|---|---|
| Apple Inc. (компания, бренд экосистемы) | Aisystant (компания, бренд экосистемы) |
| Смартфон пользователя (его устройство) | IWE пользователя (его личная среда) |
| iOS + установленные приложения | Методология + Pack-клоны + VS Code |
| Apple ID + iCloud + App Store + сервисы | Платформа Aisystant (Identity, Neon, Knowledge Index, Gateway, марафон, когорты) |
| CloudKit API (контракт устройство↔iCloud) | MCP Gateway `mcp.aisystant.com` (контракт IWE↔платформа) |
| Apple Watch = спутник без полной мощности iPhone | Telegram-бот = тонкий доступ без полного IWE |
| Приложение Pages на iPhone (сделано Apple, живёт на устройстве) | Pack-клон (создан Aisystant, управляется пользователем) |

**Граница применимости аналогии:** работает на уровне «устройство ≠ экосистема». Не работает на уровне «кто производит устройство» — Apple производит iPhone (конечный продукт), Aisystant производит IWE-шаблон (не конечный, пользователь разворачивает и кастомизирует).

**Ключевое:** смартфон ≠ часть Apple, но **подключается** к платформе. Платформа постоянно доставляет. Смартфон можно использовать без iCloud (урезанно). iCloud обслуживает и другие устройства (iPad, Mac).

### 2.2. AOSP + Google Play Services — различение «шаблон + платформа»

Для ответа на вопрос «почему мы делаем и IWE-шаблон, и платформу»:

| Android | Aisystant |
|---|---|
| AOSP (Android Open Source Project) | IWE-шаблон (FMT-exocortex-template) |
| Google Play Services | Платформа Aisystant (облачные сервисы) |
| Samsung One UI / Xiaomi MIUI | Персональный IWE конкретного пользователя |
| Qualcomm (производитель чипов) | Anthropic (поставщик Claude, runtime) |

**IWE-шаблон** = кастомизируемая база. Пользователь может «форкнуть» и отключиться от платформы (теоретически). **Платформа** = облачный бэкенд — централизована, не форкается.

Google делает и Android, и Google Play Services — но это разные продукты с разными жизненными циклами. Аналогично: Aisystant делает и IWE-шаблон, и платформу — они остаются разными системами.

## 3. Формальное различение

**IWE** (Intellectual Work Environment) — **автономная персональная среда**, развёрнутая у пользователя, которая **подключается к Платформе Aisystant через MCP Gateway** для получения сервисов (Identity, Knowledge Index, программы развития). Базовая функциональность IWE (редактирование, git, локальное выполнение скриптов) не требует подключения к платформе.

**Платформа Aisystant** — **облачный бэкенд**, единый для всех пользователей. Доставляет IWE контент, идентификацию, программы развития, сервисы сообщества.

**Это 2 разных системы с явным интерфейсом между ними (MCP Gateway).**

### 3.1. Сравнительная таблица

| Аспект | IWE | Платформа Aisystant |
|---|---|---|
| **Где живёт** | На стороне пользователя — git-репо, файловая система, VS Code | В облаке — Railway, Neon, CF Workers |
| **Кто владеет** | Пользователь | Aisystant |
| **Что содержит** | CLAUDE.md, memory/, Pack-клоны (управляет пользователь), DS-репо, локальный контекст | Identity (Ory), ЦД (Neon, вычисляется платформой), Knowledge Index, MCP Gateway, биллинг, марафон, когорты |
| **Жизненный цикл** | Эволюционирует вместе с пользователем | Обновляется командой Aisystant централизованно |
| **Обязательна** | Нет — T1–T3 работают без IWE через бот/браузер | Да — базовая инфраструктура |
| **Интерфейс к другой стороне** | MCP Gateway (со стороны IWE: MCP-клиент в настройках) | MCP Gateway (со стороны платформы: единая точка `mcp.aisystant.com/mcp`) |
| **Кто разрабатывает** | Тсерен (IWE template, Pack-контент) | Андрей (runtime, платформа) |
| **Автономность** | Работает офлайн (базовые функции) | Требует постоянного подключения |

### 3.2. Критерий размещения артефактов («кто создаёт и управляет»)

Для разграничения «гибридных» артефактов — два вопроса:

| Артефакт | Создатель оригинала | Управляет экземпляром | Принадлежность |
|---|---|---|---|
| Pack-клон | Aisystant (шаблон) | Пользователь (когда пуллить, форкать, замораживать) | **IWE** |
| ЦД (cp-профиль, прогресс) | Платформа (вычислено из activity) | Платформа (хранит в Neon) | **Платформа** |
| memory/ личные файлы | Пользователь | Пользователь | **IWE** |
| MCP Gateway config | Aisystant (спека протокола) | Пользователь (local settings) | **IWE** |
| Приложение Pages на iPhone | Apple (создала) | Пользователь (на своём устройстве) | **IWE (по аналогии)** |

### 3.3. Тест

> «Кто управляет этим экземпляром — пользователь или платформа?» → Пользователь → **IWE**. Платформа → **Платформа**.

## 4. Количество сущностей: две, не три

На встрече 20 возникла версия про **три сущности**: интерфейсы + IWE + платформа.

Из транскрипта — итоговое решение:
> «Интерфейсы, наверное, **не стоит выделять отдельно**, потому что это часть платформы. Мы включаем те интерфейсы, через которые она работает.»

**Итого: 2 сущности.** Интерфейсы входят в платформу.

Типы интерфейсов в платформе:
- **Для людей**: Telegram-бот, Web App, браузер (claude.ai MCP-коннектор)
- **Для агентов**: MCP Gateway — единая точка `mcp.aisystant.com/mcp`

Особый случай: **VS Code + Claude Code** — хост-интерфейс Anthropic (не Aisystant). Aisystant владеет только Gateway и содержимым ответа, не хостом. Конфигурация MCP-клиента в VS Code (настройки пользователя) → IWE.

## 5. Доступ к личному IWE через бот и сайт платформы

Вопрос: «А доступ через бота к личному IWE возможен и через сайт платформы я могу к своему IWE получить доступ?»

| Что | Бот | Сайт платформы / Web App | VS Code |
|---|---|---|---|
| Pack, Knowledge Index (L2) | ✅ | ✅ | ✅ |
| ЦД — Цифровой Двойник, прогресс | ✅ | ✅ | ✅ |
| Роли (Навигатор, Диагност) | ✅ | ✅ (через MCP-хост) | ✅ |
| Личные знания L4 (репо, memory/) | 🔶 WP-209 | 🔶 только через claude.ai MCP-коннектор | ✅ |
| Запись в личные репо (git) | ❌ | ❌ | ✅ |
| Протоколы ОРЗ, скрипты, хуки | ❌ | ❌ | ✅ |

**Пояснения по категориям:**

| Категория | Причина |
|---|---|
| 🔶 «не реализовано» | WP-209 в разработке; технически возможно через personal_memory_search Gateway |
| ❌ «архитектурно запрещено» | Принцип data sovereignty: сервер Aisystant не имеет доступа к git-репо пользователя |
| Запись через бота/сайт | Технически возможна (GitHub API), но требует explicit consent пользователя; не реализована |

**Архитектурное обоснование:** L4-знания хранятся в git-репо пользователя (принцип владения). Доступ к личным L4-знаниям через бот — через Gateway-инструмент `personal_memory_search`, а не через файловую систему напрямую.
