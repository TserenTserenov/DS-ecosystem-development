# WP-281 — Персональные страницы участников: фронтенд

**Руководитель:** Ильшат
**Исполнитель:** Наталья Бакулина
**Бэкенд / API:** Церен

---

## Обещание

Участник открывает свою страницу и видит текст на сегодня — упражнения и материал, подобранные под его проекты и цели. Каждую неделю система составляет недельную программу по итогам сессии стратегирования. Рядом — баллы и бонусы.

---

## Контекст: как стало понятно благодаря WP-412

Персональное руководство — это **языковой артефакт** с конкретным регистром. По онтологии WP-412 (теория регистра Холлидея):

| Ось | Что значит для WP-281 |
|-----|----------------------|
| **Поле (field)** | домен участника: его проекты, методы, цели — берётся из профиля платформы |
| **Отношение (tenor)** | регистр «академический/персональный» (WP-412 Ф9) — PACK-language-style владелец правил |
| **Канал (mode)** | браузер + мобиль (Наталья рендерит markdown в HTML) |

**Что это меняет для фронтенда:**
- Формат `guide.json` и `week/*.md` выпускает Церен — **но содержательный стиль файлов определяет WP-412 Ф9.** Ждать оба артефакта параллельно, не последовательно.
- Разметка (заголовки, ссылки, упражнения) стабильна — это жанровые конвенции регистра «руководство», которые WP-412 Ф9 зафиксирует как стандарт.
- Фронтенд не управляет стилем контента — он рендерит то, что пришло. Переключение регистра — не задача Натальи.

**Три источника данных:**

| Источник | Что отдаёт | Кто владелец |
|----------|-----------|-------------|
| GitHub-репо участника (`personal-guide/`) | контент руководства: `guide.json` + `week/*.md` | Церен (формат) + WP-412 Ф9 (стиль) |
| API платформы | имя, уровень, баллы, бонусы | Церен (endpoint) |
| Параметр URL (`/u/{username}/`) | идентификатор участника | Церен (`{username}` = GitHub-логин или внутренний ID — уточнить) |

---

## Ключевое различие: универсальное vs персональное руководство

**Универсальное** (guide.system-school.ru) — одно для всех. Уже есть.

**Персональное** — недельная программа для конкретного человека по итогам стратегической сессии. Собирается системой (не Натальей), кладётся в GitHub-репо участника. Наталья только отображает.

---

## Структура страниц

```
guide.system-school.ru/                   — общие руководства (уже есть)
guide.system-school.ru/u/{username}/      — личная страница участника
```

### `/u/{username}/` содержит:

- Имя участника и уровень
- Баллы и бонусы (что накоплено, что доступно)
- Контент текущего дня: markdown → HTML, упражнения + ссылки на материалы
- Навигация по неделе: все дни, текущий выделен, прошедшие помечены
- Пометка «программа собрана для вас» (не общий раздел)

---

## Формат контента в репо участника

```
personal-guide/
├── guide.json        — метаданные недели (даты, заголовок, список дней)
└── week/
    ├── mon.md        — полный текст: упражнения + ссылки
    ├── tue.md
    ├── wed.md
    ├── thu.md
    ├── fri.md
    └── sat.md        — если нужно
```

Точный формат `guide.json` — спецификация от Церена. Стиль разметки внутри `*.md` — WP-412 Ф9.

Способ получения — GitHub Contents API. Приватность репо — уточнить с Ильшатом и Цереном.

## Фазы

### Ф1 — Контракт: формат + стиль (~2ч)

**Задача:** зафиксировать контракт фронтенда ДО начала вёрстки.

- Получить от Церена: спецификацию `guide.json` + пример `mon.md`
- Получить от WP-412 Ф9 (или Церена): что является жанровой конвенцией регистра «персональное руководство» (уровни заголовков, блоки упражнений, ссылки)
- Решить с Ильшатом: `{username}` = GitHub-логин или внутренний ID?
- Решить с Ильшатом: страница только для владельца или доступна другим?
- Выход: `guide-format-spec.md` — фронтенд-контракт, одобренный Цереном

**Блокер:** без этой фазы Наталья верстает «по догадке». Ф2-Ф3 можно начать с мокапом, но не финализировать.

**Статус:** pending (ждём спецификацию от Церена + частичный результат WP-412 Ф9)

---

### Ф2 — Базовая страница: рендеринг + навигация по неделе (~4ч)

- Роутинг `/u/{username}/`
- Чтение `guide.json` через GitHub Contents API
- Определение текущего дня, загрузка `week/<day>.md`
- Рендеринг markdown → HTML (Naталья выбирает библиотеку)
- Навигация по неделе: все дни, текущий выделен, прошедшие помечены

**Статус:** pending (зависит от Ф1)

---

### Ф3 — Данные участника: API интеграция (~2ч)

- Получить от Церена endpoint и формат ответа (имя, уровень, баллы, бонусы)
- Карточка участника: имя + уровень
- Блок баллов и бонусов: что накоплено, что доступно

**Статус:** pending (ждём endpoint от Церена)

---

### Ф4 — Авторизация (~2ч)

- Неавторизованный → редирект на страницу входа
- Авторизованный, но чужая страница → решить с Ильшатом (ошибка или видно)
- Текущий пользователь = владелец страницы → полный доступ

**Статус:** pending (зависит от решения Ильшата о видимости)

---

### Ф5 — Пустые состояния и fallback (~1ч)

- `guide.json` отсутствует → заглушка «Пройди первую сессию стратегирования»
- Контент дня не найден → нейтральное сообщение, не сломанный экран
- API участника недоступен → показать то, что есть (контент без баллов)

**Статус:** pending

---

### Ф6 — Дизайн и адаптивность (~3ч)

- Стиль совпадает с system-school.ru (шрифты, цвета, компоненты)
- Мобильный (iPhone / Android Chrome) + десктоп
- Страница ощущается как «моё пространство», не раздел общего сайта
- Если есть дизайн-система в проекте Андрея — использовать её

**Статус:** pending (зависит от решения «берём проект Андрея или стартуем новый»)

---

### Ф7 — Деплой (~1ч)

- Выбрать хостинг с Ильшатом и Натальей (Railway / Vercel / Cloudflare Pages)
- Выкатить в продакшен, проверить по реальному URL
- Кеширование: контент из GitHub обновляется не чаще раза в день — кешировать агрессивно

**Статус:** pending

---

## Технические предпочтения

- Фреймворк: Vue / Nuxt — если совпадает с проектом Андрея, иначе на усмотрение Натальи
- На будущее: логика персональных страниц может переехать в LMS — не привязывать жёстко к guide.system-school.ru

---

## Критерии закрытия

1. Страница открывается и показывает персональное руководство, баллы и бонусы
2. Контент дня рендерится из markdown в HTML с навигацией по неделе
3. Визуально совпадает со стилем system-school.ru
4. Работает на мобильном (iPhone / Android Chrome)
5. При отсутствии контента — заглушка, не сломанный экран
6. Задеплоено в продакшен по реальному URL
