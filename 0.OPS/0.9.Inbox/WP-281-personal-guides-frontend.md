# Персональные страницы участников: задача для фронтенда

**Руководитель проекта:** Ильшат
**Исполнитель:** Наталья Бакулина
**Церен:** разработчик других частей платформы (бэкенд, API, доставка контента)
**Срок:** обсуждается

---

## Обещание

Каждый участник платформы открывает свою личную страницу и видит: персональное руководство, подобранное под его уровень развития, накопленные баллы и доступные бонусы. Всё в одном месте, в стиле school.ru.

---

## Сценарии использования

**Сценарий 1. Участник проверяет, что ему изучать дальше.**
Михаил закончил третий раздел руководства по системному мышлению. Он заходит на свою страницу, видит что этот раздел отмечен как пройденный, и переходит к следующему рекомендованному.

**Сценарий 2. Участник хочет посмотреть свои достижения.**
Анна хочет понять, сколько баллов она набрала за месяц и какие бонусы ей доступны. Она заходит на свою страницу и видит сводку: баллы, текущий уровень, доступные бонусы.

**Сценарий 3. Наставник смотрит страницу подопечного.**
Куратор открывает страницу участника по ссылке, чтобы понять, на каком этапе он находится и что актуально обсудить на встрече.

---

## Контекст: как устроена система в целом

Сайт guide.system-school.ru сейчас показывает общие универсальные руководства - одинаковые для всех. Следующий шаг - персональные страницы.

Вся система состоит из трёх частей:

**Часть 1 - то, что уже есть:** Платформа знает, на каком уровне развития находится каждый участник и что ему актуально сейчас. Там же хранятся баллы и бонусы.

**Часть 2 - делает другая задача (не Наталья):** Специальный процесс собирает персональное руководство под конкретного участника и кладёт его в его личное GitHub-репозиторий в стандартном формате. Обновляет при переходе на следующий уровень.

**Часть 3 - делает Наталья:** Красивый и рабочий сайт, который берёт этот контент и показывает участнику его личную страницу.

**На будущее:** В дальнейшем логика персональных страниц может переехать в LMS. Это важно учитывать при проектировании - не привязывать логику жёстко к guide.system-school.ru.

## Структура страниц

```
guide.system-school.ru/                          — общая часть (уже есть)
guide.system-school.ru/u/{username}/             — личная страница участника
guide.system-school.ru/u/{username}/{guide}/     — конкретное руководство
```

### Личная страница `/u/{username}/`

- Карточка участника: имя, текущий уровень, краткий прогресс
- Баллы и бонусы: сколько накоплено, что доступно
- Список персональных руководств с описанием и статусом (актуально / пройдено / рекомендую сейчас)
- Переход в каждое руководство

### Страница руководства `/u/{username}/{guide}/`

- Заголовок и описание
- Навигация по разделам (sidebar или breadcrumb)
- Контент разделов (markdown, отрендеренный в HTML)
- Заметка «это руководство собрано специально для вас» - чтобы участник понимал, что это не общая страница
- Ссылка на полную публичную версию (если есть)

## Откуда берётся контент

### Контент руководства - из GitHub-репозитория участника

Контент лежит в стандартной папке в репо пользователя:

```
personal-guide/
├── index.json           - список руководств и их статусы
└── {guide}/
    ├── meta.json        - заголовок, описание, список разделов
    └── sections/
        ├── 01-intro.md
        ├── 02-main.md
        └── ...
```

Точный формат `index.json` и `meta.json` - Церен выпустит отдельную спецификацию до начала вёрстки.

Способ получения - GitHub Contents API. Публичные или приватные репо - уточнить с Ильшатом и Цереном.

### Данные участника - из API платформы

Имя, уровень, баллы, бонусы - отдаёт существующий API. Точный endpoint и формат ответа - уточнить с Церёном.

## Требования к дизайну

- Стиль совпадает с [system-school.ru](https://system-school.ru) - шрифты, цвета, компоненты, интонация
- Адаптивность: мобильный и десктоп
- Если есть дизайн-система в проекте Андрея - использовать её, не изобретать новую
- Личная страница должна ощущаться как «моё пространство», а не раздел общего сайта

---

## Технические предпочтения

- Фреймворк: Vue / Nuxt - если совпадает с проектом Андрея, иначе на усмотрение Натальи
- Хостинг: обсудить с Ильшатом и Цереном (Railway / Vercel / Cloudflare Pages)
- Кэширование: контент из GitHub обновляется не чаще раза в день - кэшировать агрессивно
- Если репо участника не существует или контент не найден - показать заглушку «руководство ещё готовится», не ошибку

---

## Критерии: когда задача считается выполненной

1. Личная страница открывается и показывает руководства, баллы и бонусы участника
2. Страница руководства открывается и рендерит markdown-текст
3. Визуально совпадает со стилем system-school.ru
4. Работает на мобильном (iPhone / Android Chrome)
5. При отсутствии контента - заглушка, не сломанный экран
6. Задеплоено в продакшен и доступно по реальному URL
