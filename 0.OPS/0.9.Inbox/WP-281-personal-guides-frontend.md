# Персональные страницы участников: задача для фронтенда

**Руководитель проекта:** Ильшат
**Исполнитель:** Наталья Бакулина
**Церен:** разработчик других частей платформы (бэкенд, API, доставка контента)
**Срок:** обсуждается

---

## Обещание

Участник открывает свою страницу и видит одно руководство - собранное именно для него прямо сейчас. Не каталог курсов, а одна сборка: разделы из разных универсальных руководств, отобранные под его текущие проекты, цели и то, что он делал вчера. Плюс его баллы и бонусы.

---

## Ключевое различие: универсальное и персональное руководство

Это важно понять, чтобы сделать правильный фронтенд.

**Универсальное руководство** (уже есть на guide.system-school.ru) - это отдельный материал, который может прочитать любой. Например, «Системное мышление: введение». Оно одинаковое для всех.

**Персональное руководство** - это НЕ другое руководство из того же каталога. Это одна сборка, собранная специально для конкретного человека в данный момент. Система берёт фрагменты из разных универсальных руководств и составляет из них одно персональное - исходя из того, чем человек занимается, какие у него проекты, цели и пробелы в знаниях. Персональное руководство одно и обновляется по мере изменения контекста человека.

**Для Натальи:** страница показывает не список, а одно руководство с разделами. Каждый раздел может быть помечен источником (из какого универсального руководства взят).

---

## Сценарии использования

**Сценарий 1. Участник открывает своё руководство.**
Михаил ведёт проект по проектированию системы. Он заходит на свою страницу и видит персональное руководство: оно содержит раздел про декомпозицию (из универсального руководства по системной инженерии) и раздел про работу с командой (из руководства по системному менеджменту) - именно то, что нужно для его текущего проекта. Для Натальи: фронтенд получает один файл руководства с разделами и рендерит его целиком.

**Сценарий 2. Участник проверяет баллы и бонусы.**
Анна видит: 340 баллов, уровень 3, доступен бонус «1:1 с ментором» при накоплении 500 баллов. Для Натальи: API платформы отдаёт числа и список доступных бонусов.

**Сценарий 3. Пустое состояние.**
Новый участник только начал, у него нет активных проектов и действий - система ещё не собрала руководство. Страница показывает заглушку: «Начни работать в IWE - система подберёт материал под твои задачи». Для Натальи: если контент руководства пуст - показать блок по умолчанию.

## Контекст: как устроена система в целом

Сайт guide.system-school.ru сейчас показывает общие универсальные руководства - одинаковые для всех. Следующий шаг - персональные страницы.

Вся система состоит из трёх частей:

**Часть 1 - то, что уже есть:** Платформа знает уровень мастерства участника, его активные проекты, цели и неудовлетворённости. Там же хранятся баллы и бонусы.

**Часть 2 - делает другая задача (не Наталья):** Специальный процесс смотрит на контекст участника и собирает для него одно персональное руководство из фрагментов универсальных руководств. Кладёт результат в личный GitHub-репозиторий участника. Обновляет при изменении его контекста.

**Часть 3 - делает Наталья:** Красивый и рабочий сайт, который берёт собранное руководство из репозитория и показывает его участнику.

**На будущее:** Логика персональных страниц может переехать в LMS. Не привязывать жёстко к guide.system-school.ru.

---

## Структура страниц

```
guide.system-school.ru/                   — общая часть с универсальными руководствами (уже есть)
guide.system-school.ru/u/{username}/      — личная страница участника
```

Отдельной страницы для «конкретного руководства» нет - персональное руководство одно, и оно показывается на личной странице.

### Личная страница `/u/{username}/`

- Карточка участника: имя, текущий уровень
- Баллы и бонусы: сколько накоплено, что доступно
- Персональное руководство: заголовок, навигация по разделам, контент разделов (markdown в HTML)
- Пометка «собрано специально для вас» - чтобы участник понимал, что это не общее руководство
- У каждого раздела - ссылка на источник (универсальное руководство, откуда взят фрагмент)

---

## Откуда берётся контент

### Контент руководства - из GitHub-репозитория участника

Для каждого участника система собирает одно персональное руководство и кладёт его в его личный GitHub-репозиторий. Примерная структура:

```
personal-guide/
├── guide.json           - метаданные (заголовок, когда собрано, список разделов)
└── sections/
    ├── 01-thinking.md   - раздел из универсального руководства по системному мышлению
    ├── 02-projects.md   - раздел из руководства по проектной работе
    └── ...              - столько разделов, сколько актуально сейчас
```

Каждый раздел в `guide.json` может содержать ссылку на источник - какое именно универсальное руководство послужило основой.

Точный формат `guide.json` - Церен выпустит отдельную спецификацию до начала вёрстки.

Способ получения - GitHub Contents API. Публичные или приватные репо - уточнить с Ильшатом и Цереном.

### Данные участника - из API платформы

Имя, уровень, баллы, бонусы - отдаёт существующий API. Точный endpoint и формат ответа - уточнить с Церёном.

## Требования к дизайну

- Стиль совпадает с [system-school.ru](https://system-school.ru) - шрифты, цвета, компоненты, интонация
- Адаптивность: мобильный и десктоп
- Если есть дизайн-система в проекте Андрея - использовать её, не изобретать новую
- Личная страница должна ощущаться как «моё пространство», а не раздел общего сайта

---

## Доступ к странице

Страница `/u/{username}/` видна только самому участнику после входа в систему. Это не публичная страница. Наталье нужно реализовать проверку авторизации: неавторизованный пользователь перенаправляется на страницу входа. Подтвердить с Ильшатом (см. открытые вопросы).

---

## Технические предпочтения

- Фреймворк: Vue / Nuxt - если совпадает с проектом Андрея, иначе на усмотрение Натальи
- Хостинг: обсудить с Ильшатом и Цереном (Railway / Vercel / Cloudflare Pages)
- Авторизация: проверка что текущий пользователь = владелец страницы; неавторизованный - редирект на вход
- Кэширование: контент из GitHub обновляется не чаще раза в день - кэшировать агрессивно
- Если репо участника не существует или контент не найден - показать заглушку «руководство ещё готовится», не ошибку

---

## Критерии: когда задача считается выполненной

1. Личная страница открывается и показывает персональное руководство (разделы с контентом), баллы и бонусы участника
2. Разделы руководства рендерятся из markdown в HTML со структурной навигацией
3. Визуально совпадает со стилем system-school.ru
4. Работает на мобильном (iPhone / Android Chrome)
5. При отсутствии контента - заглушка, не сломанный экран
6. Задеплоено в продакшен и доступно по реальному URL
