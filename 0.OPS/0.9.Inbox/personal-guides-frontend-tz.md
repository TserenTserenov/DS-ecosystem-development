# ТЗ: Фронтенд персональных руководств на guide.system-school.ru

> Исполнитель: Наталья Бакулина.
> Срок: обсуждается.
> Этот документ описывает только фронтенд. Сборка персональных руководств и доставка в репо пользователей — отдельный РП, выполняется параллельно.

---

## Цель

Запустить в проде страницы персональных руководств на сайте [guide.system-school.ru](https://guide.system-school.ru) — так, чтобы каждый участник платформы мог зайти на свою страницу и увидеть персональное руководство, собранное под него.

---

## Контекст

Сейчас guide.system-school.ru показывает общие руководства: есть программы, в каждой — руководства, в каждом — разделы. Это общий контент для всех.

Следующий шаг — персональные страницы. Для каждого участника система собирает индивидуальное руководство (какие разделы актуальны именно ему, на основе его ступени и прогресса) и доставляет его в его личное GitHub-репо в стандартном формате. Фронтенд должен это отображать.

**Что делает другой РП (не Наталья):**
- Собирает персональное руководство под конкретного пользователя
- Доставляет его в личное репо пользователя (GitHub)
- Поддерживает актуальность (обновляет при изменении ступени/прогресса)

**Что делает Наталья:**
- Делает страницы, которые красиво и корректно отображают доставленный контент
- Обеспечивает работу в проде

---

## Структура страниц

### URL-схема

```
guide.system-school.ru/                  — публичная часть (уже есть)
guide.system-school.ru/u/{username}/     — личная страница пользователя
guide.system-school.ru/u/{username}/{guide-slug}/   — конкретное руководство
```

`{username}` — идентификатор участника (совпадает с именем GitHub-репо или другим стабильным ID, уточнить с Цереном перед стартом).

### Личная страница `/u/{username}/`

- Карточка пользователя: имя, ступень, прогресс (данные из API платформы, см. раздел «Данные»)
- Список персональных руководств с кратким описанием и статусом («актуально», «пройдено», «рекомендую сейчас»)
- Кнопка/ссылка на каждое руководство

### Страница руководства `/u/{username}/{guide-slug}/`

- Заголовок и описание руководства
- Навигация по разделам (sidebar или breadcrumb)
- Контент разделов (markdown → HTML)
- Индикатор «персонализировано для вас» — чтобы пользователь понимал, что это не общее руководство
- Ссылка на полную публичную версию (если есть)

## Данные: откуда фронтенд берёт контент

Два источника:

### 1. Личное GitHub-репо пользователя

Контент руководства лежит в репо пользователя в стандартной структуре:

```
personal-guide/
├── index.json           — мета: список руководств, статусы
└── {guide-slug}/
    ├── meta.json        — заголовок, описание, разделы
    └── sections/
        ├── 01-intro.md
        ├── 02-main.md
        └── ...
```

Формат `index.json` и `meta.json` — согласовывается с Цереном до начала верстки (выпускаем спецификацию отдельно).

**Способ получения:** GitHub Contents API (публичное репо) или GitHub API с токеном (приватное репо). Решение по видимости репо — уточнить с Цереном.

### 2. API платформы

Для карточки пользователя (имя, ступень, прогресс) — существующий API платформы. Endpoint и формат — уточнить с Цереном.

## Дизайн

- Стиль: соответствовать [system-school.ru](https://system-school.ru) — шрифты, цвета, компоненты, тон
- Адаптивность: работает на мобильном и десктопе
- Если уже есть дизайн-система у Андрея (проект, который обсуждали) — использовать её, не изобретать новую
- Персональная страница должна чувствоваться как «моё» пространство, не как раздел общего сайта

---

## Технические требования

- Фреймворк: на усмотрение Натальи (Vue / Nuxt предпочтительно, если уже используется в проекте Андрея)
- Деплой: обсудить с Цереном (Railway / Vercel / Cloudflare Pages)
- SEO: личные страницы — закрытые или с `noindex`, решить с Цереном
- Кэширование: контент из GitHub обновляется не чаще раза в день — кэшировать агрессивно (ISR или CDN-кэш)
- Ошибки: если репо нет или контент не найден — корректная страница-заглушка («руководство ещё не готово»)

---

## Чего НЕ нужно делать в этом РП

- Сборка персонального руководства — это другой РП
- Доставка контента в GitHub-репо пользователя — это другой РП
- Авторизация и личный кабинет — только если без этого невозможно показать страницу; минимально необходимое

---

## Критерии приёмки

1. Страница `/u/{username}/` открывается и показывает список персональных руководств пользователя
2. Страница руководства открывается и корректно рендерит markdown-контент из репо
3. Визуально соответствует стилю system-school.ru
4. Работает на мобильном (iPhone 13 / Android Chrome)
5. При отсутствии контента в репо показывает корректную заглушку (не 500, не пустой экран)
6. Задеплоено в прод и доступно по реальному URL
