# Повестка ИТ-встречи: разделение Россия/Мир — независимость мирового контура (WP-415)

> **Цель встречи:** ратифицировать топологию организаций + принцип независимости мирового контура + оформление мирового юрлица **Aisystant Corp**, и согласовать порядок миграции репозиториев.
>
> **Главное за 30 секунд:** платформа первична и всеядна к агентам; IWE — один из клиентов. Мировой контур не должен зависеть от российского. Канон знания живёт в мировом доме (`aisystant` под Aisystant Corp), Россия (`mimsys`) — приёмник проекции + персональные данные россиян. Полные документы — ссылки в конце.

<details open>
<summary><b>1. Что уже решено (директивы пилота — выносим на ратификацию)</b></summary>

1. **Инверсия модели.** Платформа (Aisystant) первична и assistant-agnostic: держит знание, память, руководства, сервисы и отдаёт их любому агенту. IWE — один из клиентов (дистрибутив рабочей среды), не ядро.
2. **Принцип независимости мирового контура.** Мировой контур не зависит от российского ни юридически, ни по инфраструктуре, ни по источнику знания. Тест разрываемости: «убрать российскую компанию → мировой продукт работает полностью?» = да.
3. **Мировое юрлицо — Aisystant Corp.** Владеет организацией `aisystant`, продуктом IWE, каноном знания, инфраструктурой (GKE).
4. **Дом канона — `aisystant`.** Source-of-truth канона в мировом доме (не в российском контуре). Отдельную нейтральную канон-организацию не заводим.
5. **Россия (`mimsys`) — downstream.** Получает русскую проекцию канона односторонним потоком + хранит персональные данные россиян по закону (VK). Зависит от мира; мир от неё не зависит.
6. **Мастерские.** Личный аккаунт члена команды = его мастерская (личный аккаунт + свои ИИ-агенты); изменения текут из мастерских в `aisystant`. Модель open-source: дом общий, мастерские личные.
7. **`iwesys` — дистрибутив рабочей среды** (Шаблон IWE + локальный шлюз + методы), мировой продукт. Английский; русский первоисточник временно на личном аккаунте, английская проекция через конвейер.

<summary><b>3. Модель платформы (суть)</b></summary>

В организации `aisystant` лежат части платформы, которая: (1) **открывает знание** разным агентам; (2) **даёт сервисы** разным агентам. К платформе подключаются и потребляют знание/сервисы личные ИИ-агенты участников сообщества, личные агенты членов команды и внешние ассистенты. IWE — один из таких клиентов.

Платформу развивают сами члены команды из своих мастерских своими ИИ-агентами (самоприменимость: инструмент усиления работы агентами создают те же люди теми же агентами).

```
Aisystant Corp (мировое юрлицо)
   └── организация aisystant = дом платформы + source-of-truth канона
         ▲                                   │
         │ изменения из мастерских           │ знание + сервисы через шлюз
         │ (PR / transfer)                   ▼
   мастерские членов команды          агенты-клиенты (IWE — один из;
   (личные аккаунты + ИИ-агенты)      личные агенты участников/команды;
                                      внешние ассистенты)
         │ (downstream, односторонне)
         ▼
   российский контур mimsys (проекция канона + персональные данные россиян)
```

Подробно: концепция §1a (инверсия), §1c (платформа и мастерские), §5a (принцип независимости).

</details>

<details>
<summary><b>4. Порядок миграции (кратко)</b></summary>

1. Оформить Aisystant Corp (предусловие).
2. Подтвердить топологию + создать организации (`mimsys`, `mim-guides`, `aisystant-guides`).
3. Консолидировать канон-источник в `aisystant` (паки из плана); `PACK-personal` уже на месте.
4. Настроить односторонний поток проекции канона мир→`mimsys`.
5. Тест разрываемости в стейджинге: отключить `mimsys` → мир работает.
6. Перенести продукт в `iwesys` + конвейер текстов среды.
7. Публичный запуск `iwesys` после готовности английского ядра канона.

Полный план с раскладкой 26 репозиториев: `WP-415-migration-plan.md`.

</details>
