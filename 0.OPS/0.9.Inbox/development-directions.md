# Направления плана развития платформы Aisystant и системы IWE

> **Контекст:** после пивота продукта (курсы → платформа+IWE) и формирования новой архитектуры (WP-73, WP-336) требуется системный план развития. Направления ниже — не roadmap с датами, а стратегические векторы с приоритетами, owner'ами и критериями готовности.
>
> **Принцип:** каждое направление = цель + 3-5 ключевых проектов + метрика успеха + зависимости.

---

### Ключевые проекты

|---|--------|-------|---------------------|-------------|

| 1.2 | **Track B: Ory EU** | Андрей | Ory EU инстанс LIVE, независим от RU | Cloud SQL, GKE |
| 1.3 | **Track B: Stripe + юрлицо** | Тсерен / юрист | Stripe аккаунт LIVE, первый платёж прошёл | UK Ltd / US LLC / Кипр — решение |
| 1.4 | **Track A: передача Ильшату** | Ильшат / Тсерен | Bus factor ≥2, deploy doc готов, Ильшат может деплоить без Андрея | WP-281 handoff |

### Метрики успеха
- Track B: первый сервис деплоится на GKE до 1 июля 2026
- Track A: Ильшат делает самостоятельный деплой до 1 июня 2026

## Ключевые зависимости между направлениями

```
1. Инфраструктура
   ├── блокирует: 2 (IWE Ядро) — Web App нужен GKE/Cloud SQL
   ├── блокирует: 4 (Платформа) — сервисы нуждаются в деплое
   └── блокирует: 3 (AI) — Agent Workshop нужен GKE

2. IWE Ядро
   ├── блокирует: 6 (Маркетинг) — лендинг без Web App = пустой CTA
   └── блокирует: 5 (Экосистема) — клуб нужен единый identity

3. AI и Агенты
   └── блокирует: 4 (Платформа) — ДЗ-чекер, ЦД v2 нужны агенты

4. Платформа
   ├── блокирует: 2 (IWE Ядро) — Web App нужен Billing, ЦД
   └── блокирует: 6 (Маркетинг) — кейсы нужны реальные пользователи

7. Безопасность
   └── блокирует: ВСЕ — без B7.3 и GDPR нет прод-релиза новых сервисов
```

## Рекомендации по приоритетам

1. **P0 — Критический путь:** 1.1 (Track B GKE) + 7.1 (B7.3) + 2.1 (Web App MVP) — без этого нет продукта для масштаба
2. **P1 — Ускорители роста:** 3.1 (Agent Workshop) + 6.1 (Pitch v1.0) + 4.1 (ЦД v2) — дают конкурентное преимущество
3. **P2 — Масштабирование:** 1.4 (Track A handoff) + 5.3 (Региональный сплит) + 6.3 (Outbound) — позволяют расти без линейного роста команды
4. **P3 — Оптимизация:** всё остальное — делается по мере освобождения ресурсов
