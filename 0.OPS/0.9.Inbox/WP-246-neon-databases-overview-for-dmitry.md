# Как устроены базы данных для платежей, подписок и баллов

Материал для Дмитрия Стародубова — ответ на вопрос, что за базы данных сейчас используются и стоит ли новому сервису платежей заводить отдельную базу.

## Общая картина

Сейчас это не одна большая база, а примерно десяток отдельных баз данных в одном облачном сервере баз данных (Neon). Каждая база отвечает ровно за одну область — платежи отдельно, подписки отдельно, баллы отдельно и так далее. Базы не работают в изоляции: когда что-то происходит в одной из них, об этом узнают остальные — через общий поток событий ("платёж прошёл", "подписка продлена") — и сами обновляют то, что их касается. Ручной синхронизации между базами не требуется.

## Базы, которые касаются платежей

1. **Платежи.** Сами платежи, чеки, возвраты и то, как каждый платёж делится между получателями (организация, автор курса, наставник).
2. **Подписки.** У кого какая подписка сейчас действует, до какого числа, продление / пауза / отмена.
3. **Тарифы и справочники.** Список продуктов, которые можно купить, и цены на них.
4. **Баллы.** Бонусные баллы: кому сколько начислено и списано.
5. **Хранилище банковских карт.** Отдельная, специально защищённая база — только токены сохранённых карт для повторного списания. Изолирована от остальных намеренно, по требованиям безопасности к платёжным данным (не по границе между компаниями).
6. **Связи между людьми.** Рефералы, наставничество, амбассадорство — кто кого пригласил, кто чей наставник.

Есть ещё база с профилями пользователей (общий счёт, к которому привязаны платежи и подписки конкретного человека) и несколько баз для частей платформы, которые платежей не касаются (обучение, аналитика, публикации) — упоминаю для полноты картины, в интеграцию по платежам они не входят.

## Что уже работает в проде

Для оплаты звёздами в Telegram цепочка полностью автоматическая: бот сообщает "платёж прошёл" → подписка продлевается и баллы начисляются сами, без ручной работы. Оплата через ЮKassa в боте устроена по той же схеме, включение — на подходе.

## Почему это может быть полезно для вашего нового сервиса

Вместо отдельной базы под новый сервис можно писать прямо в эту уже готовую и разделённую структуру — тогда подписки, баллы и открытие доступа продолжат работать автоматически, без дополнительной синхронизации между вашей базой и нашей.

## Про пользователей из-за рубежа

Отдельная история: платежи не из России идут через другого провайдера, на другой инфраструктуре, с другим юридическим лицом — не пересекаются с базами выше. Ни новому сервису, ни боту взаимодействовать с этой частью не нужно.
