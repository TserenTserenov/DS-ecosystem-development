# Баг-пакет: три дыры в наблюдаемости (P1, выявлены 2026-06-15)

## Баг 1: Нет бизнес-алерта на LDAU=0

**Симптом:** Daily-отчёт содержал `LDAU = 0` и тренд `-66.7% WoW`, но отдельного Telegram-алерта не было.
Пилот узнал только из ежедневного отчёта в 04:00 — без красной иконки, без push-уведомления.

**Почему критично:** LDAU=0 = ни один пользователь не сделал учебного действия за 24 часа.
Для продукта, ориентированного на учебные действия, это ключевая бизнес-метрика.
Алерт должен быть отдельным, чтобы пилот мог среагировать до следующего утра.

**Фикс:** Добавить проверку `LDAU == 0` в скрипт daily-отчёта → отдельный TG-алерт 🔴 при срабатывании.
Порог: `LDAU = 0` или `LDAU < N (настраиваемый минимум)`.

## Баг 2: Нет прямого health-check на LLM-endpoint

**Симптом:** 403 от OpenRouter обнаружился через downstream-эффекты (ошибки в боте, дневной отчёт).
Между началом сбоя (05:15) и обнаружением прошёл час.
Нет канала алертинга, который бы напрямую пробовал `/v1/chat/completions` и кричал при 4xx.

**Почему критично:** LLM = критическая зависимость всех умных функций бота.
Без health-check на endpoint сбой LLM «невидим» до тех пор, пока пользователи не начнут жаловаться.

**Фикс:** Добавить probe-запрос (минимальный `/v1/chat/completions` с `max_tokens=1`) в cron каждые 5 мин.
При статусе `!= 200` → немедленный TG-алерт 🔴 с кодом ответа и сообщением ошибки.
Кандидат для размещения: `tsekh-1` (уже запускает overnight-auditor) или отдельный Railway-сервис.

## Баг 3: Дублирование daily/weekly отчётов (04:00 и 04:05 одинаковые данные)

**Симптом:** 2026-06-15 в 04:00 пришёл «Ежедневный отчёт» и в 04:05 «Еженедельный отчёт» — содержимое идентично.
Оба показывают данные за 24 часа (`Сессии (24ч): 73`), хотя weekly должен агрегировать 7 дней.

**Почему критично:** Дублирование создаёт шум и снижает доверие к алертам.
Weekly-отчёт с данными за 24ч — это неправильная метрика для принятия решений.

**Вероятные причины:**
1. Weekly отчёт запускается по тому же расписанию (или почти тому же) что и daily.
2. Weekly отчёт читает те же данные (24ч вместо 7д).

**Фикс:** Исправить расписание (например, weekly только по понедельникам) И/ИЛИ исправить временное окно агрегации в weekly-скрипте.
