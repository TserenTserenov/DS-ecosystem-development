# Постмортем инцидента: <краткое название>

> Шаблон WP-244 Ф11 (SOTA-аудит 21 июня 2026: GitHub/Stripe публикуют постмортемы после каждого P1).
> Процесс: инцидент **P1** (даунтайм >30 мин или потеря данных) → постмортем в течение **48 часов** → ссылка опубликована в TG-канале **@aisystant_status**.
> Заполняется владельцем инцидента (кто диагностировал и чинил). Хранение: `observability-archive/postmortems/YYYY-MM-DD-<slug>.md`.

## Метаданные

| Поле | Значение |
|------|----------|
| Дата инцидента | YYYY-MM-DD |
| Severity | P1 (даунтайм >30 мин / потеря данных) / P2 (деградация <30 мин) |
| Длительность | HH:MM → HH:MM UTC (X мин) |
| Затронутые сервисы | например: aist-bot, gateway-mcp, Neon pooler |
| Затронутые пользователи | число или «все» / оценка по user_id из health.internal_metrics |
| Обнаружен через | алерт (health-alerter / Better Stack) / жалоба пользователя / случайно |

## Таймлайн инцидента

> Все времена UTC. Факты, не интерпретации.

| Время | Событие |
|-------|---------|
| HH:MM | Начало деградации (по метрикам) |
| HH:MM | Обнаружение (алерт / жалоба) |
| HH:MM | Начало диагностики |
| HH:MM | Коренная причина найдена |
| HH:MM | Фикс применён |
| HH:MM | Восстановление подтверждено метриками |
