# Установочная встреча S1 — playbook наставника

> Обезличенная, повторно применимая версия опыта подготовки и проведения установочной встречи. Даты и имена конкретной когорты — в `../../../../.../MC-sessions` и локальных заметках наставника, не здесь.

## 1. Чек-лист подготовки (по дням до встречи)

1. **За 5-7 дней:** проверить структуру `01-presentation-structure.md` — тайминг по блокам, содержательное ядро, актуальные имена практикумов (S0-S3, канон §2б).
2. **За 3-5 дней:** обновить сценарий ведущего `02-kickoff-presentation.md`; сверить с последней версией руководства и с содержательным ядром S2 (общие блоки должны совпадать буквально, вариативные — осознанно расходиться).
3. **За 2-3 дня:** собрать слайды `03-kickoff-slides.md`, экспортировать PDF; проверить, что картинки в `assets/` актуальны (не тянуть картинку с чужого потока без явной проверки, что указатель «вы здесь» не сбивает).
4. **За 1-2 дня:** прогон с сораз работчиком/наставником-напарником; отдельно — прогон по PDF с человеком, не участвовавшим в написании (свежий взгляд ловит то, что автор больше не видит).
5. **В день встречи:** закреп в чате с правилами онлайн-общения и ссылкой на встречу; технический стек (полный список — не зачитывать на встрече, отдельным сообщением до занятия 1).

## 2. Общее ядро встречи (не резать) vs вариативная часть

**Ядро, общее для S1 и S2** (порядок может немного отличаться, содержание — нет):
- Команда практикума + правила онлайн-общения.
- Круг знакомства (кто, чем занимается, ожидания, слот времени в неделю) — ЯДРО.
- Мировоззрение: человек как система, «железный человек» и 4 мастерства.
- Путь по ступеням ученика (случайный → проактивный) с привязкой к текущему потоку.
- IWE/экзокортекс как инструмент практикума, ежедневный слот, показатель недели.
- Вопросы, задание на неделю, рефлексия одним инсайтом — ЯДРО.

**Вариативная часть (S1-специфика):** свой личный проект-проба (не рабочий), три критерия входа (не горящая проблема, результат зависит от своих действий, первый шаг обратим), формат живого упражнения — разбор 2-3 формулировок вслух через «один сеанс - три результата».

**Порядок резки при нехватке времени (сверху вниз, до компакта 60 мин):** технический стек (в отдельное сообщение) → длина круга знакомства → метафора «железный человек» (оставить тезисно). Круг знакомства, установка на внимание и договорённость о слоте — не резать никогда.

## 3. Пакет после встречи (в тот же день)

Через IWE или вручную, из транскрипта встречи собираются три материала:

1. **Памятка-закреп для чата** — короткий пронумерованный список действий первой недели (не абстрактный чек-лист: конкретные шаги, см. урок ниже).
2. **Шаблон сообщения наставнику о своём проекте** — форма из 6-9 коротких пунктов (чем занимаюсь → что не устраивает → предварительное название проекта → рабочий продукт недели → критерий готовности → сколько времени могу выделять).
3. **Разбор 3-4 живых формулировок** по схеме «с чем пришёл → что уточнили → какой рабочий продукт → как проверить» — материал для следующих потоков и для самого наставника.

Правило извлечения знания из транскрипта: сначала обезличенные различения и методы → в универсальные материалы; личные истории, номера счетов, детали работодателей — только в локальном протоколе встречи, не в публикуемых материалах.

## 3а. Досье минимального роста (РП587, с недели 2)

Тройка «ограничение / что сделали / было-стало» по каждому кейсу хот-сита фиксируется в записи ведущего (`02-meeting-structure.md`, «После встречи»). Дополнительно на этом этапе:

- **Тест главного ограничения.** Перед тем как записать «ограничение», проверить вслух с участником: «это правда то, что тормозит сильнее всего прямо сейчас, а не просто одна из помех» — иначе запись случайная, не показательная.
- **Проверка устойчивости через 2-4 недели.** Для кейса, разобранного на этой встрече, на встрече через 2-4 недели (или в опросе систематичности, если явной встречи не будет) задать участнику один вопрос: «то, что мы тогда поправили, — всё ещё держится?» Ответ (да/нет/частично) дописывается к исходной записи кейса тем же наставником. Без этого шага кейс не годится для досье — только «было-стало» без проверки на откат.

## 3б. Дополнительная встреча как клиника затруднений

Дополнительная встреча не заменяет основное занятие и не добавляет новую лекцию. Участник приносит один текущий затык и живой артефакт проекта; ведущий помогает локализовать ограничение и закончить встречу проверяемым следующим ходом.

Порядок одного хот-сита:

1. Назвать желаемое изменение и наблюдаемый рабочий продукт, которого сейчас не хватает.
2. Развести целевую систему, систему создания и систему-в-роли; исправить путаницу «система / метод / действие / рабочий продукт».
3. Найти первую стадию, где ожидание расходится с фактом, и проверить, действительно ли это главное текущее ограничение.
4. Выбрать одно минимальное вмешательство, не перестраивая одновременно весь проект.
5. Назвать показатель следующего цикла и записать гипотезу: что меняем, почему и какой эффект ожидаем.
6. Зафиксировать тройку «ограничение / вмешательство / было-стало» для РП587. Пока нет повторного замера, это гипотеза и учебный кейс, а не доказательство эффекта программы.

Банк обезличенных переносимых кейсов из дополнительной встречи 23.09.2026:

| Кейс | Одно различение для обучения | Вопрос переноса на проект участника |
|------|------------------------------|------------------------------------|
| Мероприятие по восстановлению человека | само мероприятие — целевая система; организатор — система создания; один человек может исполнять роли в обеих | «Что вы создаёте, а какая система это создаёт?» |
| Развитие владения английским | развитый человек — целевая система; обучение и продвижение — разные подсистемы создания; детализируется текущее ограничение | «Какая подсистема сейчас ограничивает результат сильнее остальных?» |
| Переход от поиска работы к работе | минимальный конвейер нужно запустить до завершения полной модели и получать обратную связь реального рынка | «Какой минимальный цикл уже можно провести и показать?» |
| Конвейер с недельными показателями | объём на входе и конверсия между стадиями показывают разные ограничения; изменение метода записывается как гипотеза | «На какой первой стадии план разошёлся с фактом?» |

Один кейс используется для одного различения, а не пересказывается целиком. Имена, работодатели, медицинские предположения и узнаваемые детали в материалы не переносятся. Числа участника остаются стартовыми гипотезами, а не нормативами программы.

## 4. Уроки первого потока (обезличено, для повторного применения)

- **Абстрактный чек-лист неоперационен.** Список «держать слот», «показать рабочий продукт» без глаголов действия участники не могут выполнить — заменять на пронумерованный список конкретных шагов с именем действия в начале каждого пункта.
- **Ценность — до устройства программы.** Слайд «одна сессия - три результата» работает лучше в начале встречи (после «свой проект»), чем в середине: сначала зачем это участнику, потом как это работает.
- **Явный дедлайн решения об участии** (например, «до среды») снижает число повисших контактов лучше, чем открытое приглашение «подумайте».
- **Явная граница обещания курса.** Курсовая нагрузка 3-5 ч/нед — не гарантия перехода на следующую ступень; ступень подтверждается отдельно по накопленным свидетельствам, это стоит произносить вслух на установочной, а не только держать в методичке.
- **Спокойный вход важнее рывка.** Явная рекомендация не увеличивать нагрузку резко в первую неделю снижает перегорание сильнее, чем мотивационный призыв «успеть больше».
- **Три критерия входа для личного проекта** (не горящая проблема / результат зависит от своих действий / первый шаг обратим) работают лучше одной фразы «выберите что-то безопасное» — участники быстрее находят подходящий пример.
