# Банк персон-скептиков Лида

Именованные архетипы возражений реального Лида: портрет + скрытые допущения («мемы-убеждения») + триггер отторжения. Назначение — адверсариальная проверка коммуникации Конвейера продвижения (посты, слайды, сообщения бота, письма) до публикации.

## Что в папке

| Файл | Что хранится |
|------|--------------|
| `personas.md` | Данные: блоки персон (портрет, мемы-убеждения, триггер отторжения, источники, история обновлений) + процесс наполнения (§Как наполнять) |
| `README.md` | Этот файл: процессы использования банка |

Первый прецедент применения: карта возражений марафона волны-2 (WP-330) — панель из 6 персон нашла 40 реальных дефектов формулировок за один прогон.

## Процесс 1 — рефлекс (человек, без ИИ)

**Триггер:** пилот/Алёна готовится опубликовать материал Конвейера продвижения (пост, слайд, сообщение бота, письмо).

**Шаг:** держать перед глазами портреты персон из `personas.md` и мысленно прогнать текст через каждую до отправки: «что здесь оттолкнёт Скилю? за какую фразу зацепится Федор?». Быстрая версия без агента, годится для коротких текстов и правок на ходу.

## Процесс 2 — ИИ-режим (панель агентов-скептиков)

**Триггер:** тот же, для материалов, где цена ошибки выше короткой правки (карта возражений, серия писем, лендинг, слайды встречи).

**Механика** (по образцу первого прогона WP-330):
1. Панель субагентов — по одному на **подтверждённую** персону из `personas.md`; каждому в промпт кладётся полный блок его персоны (портрет + мемы-убеждения + триггер отторжения). Блоки-гипотезы из внешних источников (пометка в самом блоке, например «Технократ в кризисе») в панель не включаются до подтверждения данными реальных пользователей.
2. Задача каждого агента — опровергнуть/отвергнуть текст со своей позиции: что именно оттолкнёт, какая фраза ломает доверие, чья валюта аргумента подменена.
3. Результат — список конкретных находок с привязкой к фразам текста, **не** агрегатный балл. Находки правятся автором, спорные — решает публикующий.

**Где вызывается:** любой агент с инструментом субагентов (Agent tool); промпт-шаблон = блок персоны + проверяемый текст + инструкция «опровергай, называй конкретные фразы».

## Когда прогон обязателен

Перед публикацией **любого** материала Конвейера продвижения — не только марафона (решение пилота 10.07.2026, WP-251).

Слои нормы (не противоречие, а уровни):
- Уровень Service Clause (`ECO.SC.003-promotion-service`): прогон = `may` — метод не входит в инвариант/режим отказа сервиса (консенсус Ф0 WP-251).
- Уровень операционного процесса публикации: прогон = обязательный шаг чеклиста.

Формальный чеклист-пункт в процессе публикации и передача правила Алёне — фаза Ф4 WP-251 (governance-документ `promotion-service-governance.md`).
