# Шаблон описания целевой аудитории (13 блоков)

> **Как пользоваться:** скопировать файл → назвать `<id>-<slug>.md` (например `A-independent-professional.md`) → заполнить блоки 1-6 и 8-13 (фаза Ф3), блок 7 — отдельной фазой Ф4.
> **Принцип:** блок без данных лучше честно пометить `нет данных`, чем заполнить домыслом. Источник каждого утверждения — в блоке 13.
> **Методы-источники** блоков названы в подзаголовках — это sota-рамки описания аудиторий, синтезированные под экосистему (персоны Купера, JTBD Кристенсена/Ульвика, канва ценностного предложения Остервальдера, негативная персона, закупочный центр B2B, концепция применения из системной инженерии, карта пути клиента + воронка AARRR, диффузия инноваций Роджерса, TAM/SAM/SOM).

## 2. Портрет и адрес *(персоны + Роджерс + TAM/SAM/SOM)*

- **Профессиональный адрес:** профессия, роль, возраст, калибр (Я/команда/организация/сообщество).
- **Психографика:** состояние (например Хаос / Тупик / Поворот), отношение к ИИ и развитию.
- **Где обитают:** каналы, площадки, сообщества — где этого человека физически найти.
- **Размер и платёжеспособность:** оценка сегмента (TAM/SAM/SOM), готовность платить, ожидаемый средний чек.
- **Стадия принятия новинок:** новаторы / ранние последователи / раннее большинство — определяет язык и уровень «сырости» продукта, который сегмент терпит.
- **Тон при обращении к сегменту:** что меняется в звучании (лексика, темп, с чего начинать разговор) именно для этого человека. Базовые правила разговорного стиля (DP.SC.050) одинаковы для всех сегментов и не переопределяются здесь — это только «в чём разница», а не отдельный стиль с нуля.

## 7. Сценарии использования и «правила эксплуатации» *(концепция применения; заполняется фазой Ф4)*

Автомобильная аналогия: мало продать машину — нужны ПДД, правила безопасности и обучение вождению.

- **7а. Сценарии «поездок»:** типовые ситуации применения технологий (в т.ч. IWE) этим сегментом — от первого запуска до ежедневного ритма. Минимум 3 сценария, разные контексты.
- **7б. «ПДД» и безопасность:** правила работы с данными и приватностью, что делать нельзя, зоны риска (личные данные, доступы, публикации).
- **7в. Методы управления:** какие методы человек осваивает и в каком порядке (по этапам пути), связь со ступенями/степенями.
- **7г. Требования к «водителю»:** что нужно от человека — время (ч/нед), оснащение (устройства, подписки), дисциплина (ритм, ритуалы), предпосылки входа (что должен уметь до старта).

> Не дублировать «Концепция использования созидателя 1.2» (пять системных уровней) — здесь per-сегмент конкретика, там универсальная рамка.

## 8. Путь клиента *(карта пути + воронка AARRR + модель состояний)*

- Осведомлённость → интерес → активация → оплата → удержание → рекомендация: каналы и артефакты на каждом шаге (лид-магниты, посты, марафон, семинары).
- Связка с осями платформы: путь по тирам (T0→T4) и пользам новичка (P1-P9) — в терминах ЭТОГО сегмента.
- **Маршрут по осям состояний пользователя** (модель WP-457, реестр `DS-my-strategy/inbox/WP-457/state-axes-registry.yaml`): стартовый профиль сегмента (где он по осям разрешений / оснащённости / увлечённости / компетентности) → целевой маршрут переходов. У каждого перехода есть роль-владелец — путь клиента пишется на этом языке, не свободным текстом. Пример: тёплая база стартует с высокой компетентностью и нулевой оснащённостью; новичок-предметник — наоборот.

## 9. Путь в сообществе

- Лестница: потребитель → участник клуба → сопроизводитель → наставник/автор.
- Роль-актор экосистемы (стажёр / резидент / наставник / автор продуктов / разработчик).
- Что сегмент даёт сообществу (не только берёт).
