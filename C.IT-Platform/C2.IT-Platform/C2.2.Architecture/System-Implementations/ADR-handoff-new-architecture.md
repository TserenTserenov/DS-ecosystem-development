# ADR (proposed): регламент передачи новой архитектуры

> **Статус: proposed, не канон.** Не дублирует канон — собирает уже принятые различения (разбросанные по РП73/РП401/РП415) в один компактный пакет для async-ок Андрея и Ильшата. Ратификация → каноническая топология в Pack (РП73 Ф6).

## 1. Поток передачи (3 роли)

```
Церен (архитектор новой архитектуры, строит и доводит до работоспособности)
   │
   ├──→ Андрей — Мир (трек В): владелец мирового контура после передачи
   │
   └──→ Ильшат — Россия (трек А): владелец российского контура после передачи
```

Церен строит новую архитектуру целиком и отдаёт её в оба направления. Андрей и Ильшат — не последовательные звенья одной цепи, а два параллельных получателя разных контуров.

## 2. Track A/B — ось географии, не ось поколения архитектуры

**Трек = страна назначения, не «старое/новое».**

| Трек | Дом | Владелец после передачи | Инфраструктура |
|------|-----|--------------------------|-----------------|
| А | Россия | Ильшат | Российская (VK Cloud, Cloudflare Track A), рубли |
| В | Мир | Андрей | Мировая (Google Kubernetes + европейский вход) |

**Оба трека — на новой архитектуре.** Разделение старая/новая архитектура — отдельная, ортогональная ось (миграция), не подписана ни на один трек. Полная модель — `PACK-digital-platform/.../DP.D.253-object-tiering-model.md §5`.

## 3. Две организации по юрисдикции

Разделение GitHub-организаций (РП401): русскоязычные репозитории закрываются (приватные) в `aisystant`; конвейер автоперевода публикует англоязычную проекцию; отдельный конвейер автопубликации выпускает те же материалы в организацию МИМ (русскоязычный читатель). Механизм публикации — не fork/transfer, а конвейер по событию commit, без явного git-следа связи между организациями.

**Статус исполнения:** конвейер остановлен биллинг-инцидентом (РП401), не завершён на момент этого документа — регламент передачи не блокируется завершением РП401, но подтверждает его целевую топологию как часть общей архитектуры.

## 4. Тест разрываемости (severability)

**Тест:** «убрать российскую компанию → мировой продукт работает полностью?» Ответ должен быть «да».

**Направление зависимости одностороннее:**

```
мировой контур (source-of-truth канона, продукт) — НЕЗАВИСИМ
   │ (односторонний поток: проекция канона на русскую раздачу)
   ▼
российский контур (персональные данные россиян + русская раздача + рубли) — ЗАВИСИТ от мира
```

Мир → Россия можно (проекция канона). Россия → мир (для того, что миру нужно для работы) — нельзя. Канон знания НЕ переносится в российский контур — это сделало бы мир зависимым от России. Источник: `WP-415-russia-world-split-concept.md §5a`.

## 5. Тиринг объектов

Полная модель — `PACK-digital-platform/.../DP.D.253-object-tiering-model.md` (промотирована в канон 2026-07-18). Кратко: объекты делятся на **артефакты** (тир платформенный/командный/личный — кому доставляются) и **сервисы** (дом/трек × поколение × тенантность — где работают и к ним подключаются). При передаче трека важно не путать: артефакт передаётся копированием в новый канал доставки, сервис — передачей владения работающим инстансом.
