# ADR: Топология системы персональных руководств

## Контекст

Вопрос пилота: где хранятся общие материалы, где собирается персональное руководство, где отображается. Два ограничения, заданные пилотом, отсекают наивный ответ «всё на платформе»:

1. **Не у всех есть IWE** — платформа обязана обслуживать обычного пользователя целиком.
2. **У кого есть IWE — не хотят отдавать личные данные на платформу** — суверенность данных.

Эти ограничения превращают вопрос «одно место сборки или два» в вопрос **резидентности данных по зонам доверия**.

## Решение (ArchGate PASS, критичны Эволюционируемость + Безопасность)

Разделяем три ранее смешиваемые сущности: **метод** ≠ **место исполнения / резидентность данных** ≠ **поверхность отображения**.

### Слой 1 — Хранение общих материалов: ПЛАТФОРМА
- Канон (источник истины «что существует») = Pack.
- Скомпилированные универсальные руководства + программные seed + знания = единое хранилище платформы (knowledge-сервис, отдаётся read-only). Все читают одно и то же; не дублируется по пользователям, не в личных репо.

### Слой 2 — Метод vs Исполнение (ключевое различение)
- **Метод сборки** (логика Портного + промпты) — **единый**, версионируется на платформе, **раздаётся** клиентам (тянется обновлением, не копируется руками → нет дрейфа).
- **Место исполнения + резидентность личных данных** — **по зоне доверия**:
  - **Нет IWE** → сборка на платформе (данные платформенные, своей среды нет).
  - **Есть IWE** → сборка **локально**; личные данные (профиль, RCS, контекст, рефлексии) **не уходят** на платформу; из платформы тянется только общий материал + свежий метод (чтение).
- Это НЕ «суть протекла в интерфейс»: суть (метод) единая; различается зона исполнения по приватности.

### Слой 3 — Отображение: поверхность ≠ сборка ≠ хранение
- Поверхность по умолчанию для всех = персональная страница `guide.system-school.ru` (витрина, WP-426).
- IWE-пользователь держит руководство в своём репо (VS Code primary); чтобы показать на витрине — **явно подключает репо**, публикуется **только готовое руководство** (`guide/`), не сырые данные.

## Профиль ЭМОГССБ

| Характеристика | Статус | Обоснование |
|---|---|---|
| Эволюционируемость | ✅ | Единый метод, клиенты тянут; общий материал централизован → замена без форка |
| Масштабируемость | ✅ | Локальная сборка IWE разгружает платформу; non-IWE — на платформе |
| Обучаемость | ⚠️ | Два пути исполнения → описать «где собирается моё» |
| Генеративность | ✅ | Платформа assistant-agnostic сервис; IWE — суверенный клиент |
| Скорость | ✅ | Сборка асинхронная; локально быстрее |
| Современность | ✅ | Local-first + суверенность данных + общий метод = актуальный приватный паттерн |
| Безопасность | ✅ | Личные данные IWE остаются локально (сильнее, чем «всё на платформе»). ⚠️ остаётся: подлинность раздачи метода/материала; host-орг общего материала (WP-401); область публикации на витрину |

Вето-фильтр: блокеров нет, критичные обе ✅ → проходит.

## Negative Branch Reservation (риски + парирование)

| # | Риск | Вер. | Ущерб | Парирование |
|---|------|------|-------|-------------|
| 1 | Дрейф метода (локальный IWE на старой версии → расходящиеся руководства) | средн. | средн. | Версионировать метод; тянуть свежий при каждой сборке; сторож ловит расхождение версий |
| 2 | IWE-пользователь при подключении репо публикует сырые личные данные | средн. | **высок.** | Публиковать только `guide/` (готовое руководство); сырой контекст/память исключить из области подключения |
| 3 | Не решён org-split (WP-401) → платформа/IWE тянут общий материал из разных орг → устаревший/пустой | **высок.** (уже происходит) | средн. | Каноническая орг-хозяйка общего материала = `aisystant` (per DS-ecosystem CLAUDE.md §4.8); и платформа, и IWE тянут оттуда |

## Открытые следствия (реализация — отдельными фазами)

1. **Источник знаний (блокер depth):** tsekh-1 тянет личный форк без seed; канонический `aisystant` имеет seed уровней 1-7. Переключить remote (действие пилота — прод-сервер).
2. **Переразметка вывода:** руководство = учебный текст, задание/статистика → табло (контракт PD.WP.019). Делать после подключения источника (иначе генератор фабрикует).
3. **Резидентность для IWE:** локальный путь сборки должен читать общий материал/метод с платформы, личные данные — только локально.
4. **Защита публикации на витрину:** ограничить область подключаемого репо файлами `guide/`.
